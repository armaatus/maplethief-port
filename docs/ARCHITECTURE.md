# Architecture (proposal)

> Status: **proposal**. Each major choice below is confirmed, refined or replaced by an ADR in `docs/adr/` (the issues that own each decision are named inline). Once an ADR is accepted, update this document to match it and link the ADR.

Facts referenced here come from [ANALYSIS.md](ANALYSIS.md).

Accepted decisions so far:

- [ADR 0002](adr/0002-language-and-toolchain.md): languages, minimum toolchain versions, formatting and linting.
- [ADR 0003](adr/0003-dependencies.md): third-party libraries, their pinned versions, and how the build fetches them ([THIRD_PARTY.md](../THIRD_PARTY.md)).
- [ADR 0004](adr/0004-build-presets-and-generators.md): CMake presets, generators, compiler flags and the headless smoke test.
- [ADR 0005](adr/0005-test-harness.md): test layout, `scripts/test`, the `real_assets` marker and the golden-image helper.
- [ADR 0006](adr/0006-continuous-integration.md): GitHub Actions CI, what runs on which OS and when, and how CI is kept away from the IPA; since #113 it runs on pull requests and manual runs only (Release jobs on manual runs), optionally on self-hosted runners.
- [ADR 0007](adr/0007-re-tooling-ghidra.md): RE tooling: pinned headless Ghidra 12.2 + JDK 25 driven by PyGhidra scripts, the deterministic export schema and the `work/re/names/*.json` naming contract ([tools/ghidra/README.md](../tools/ghidra/README.md)).
- [ADR 0008](adr/0008-cpp-rtti-and-virtual-function-names.md): C++ classes and vtables are recovered from the Mach-O's RTTI binds by `tools/mtport/rtti.py`, with `Class::vfN` / `~Class` / `@thunk` / key-derived method names ([docs/re/cpp-classes.md](re/cpp-classes.md)).
- [ADR 0009](adr/0009-re-analysis-outputs.md): RE analysis outputs: Capstone `armscan` as a second xref source cross-checked with Ghidra, `libtags`' ordered first-claim-wins tag rules, and generated docs in `docs/re/` (new docs: generated blocks inside hand-written Markdown) built from the canonical export of `scripts/re-analyze`.
- [ADR 0010](adr/0010-asset-pipeline-and-viewers.md): asset pipeline and viewers: one standard-library Python renderer (`tools/mtport/png.py`) produces every pixel, and the map, sprite and table viewers are generated static HTML pages under `assets-out/viewers/`, each with a batch mode.
- [ADR 0011](adr/0011-asset-pipeline-manifest-and-incremental-runs.md): asset pipeline manifest: every bundle file gets one rule (converted / copied / ignored with a reason) from `mtport.formats`, `assets-out/manifest.json` records content and output hashes, and rule keys hash the parser source so a code change invalidates its outputs.
- [ADR 0012](adr/0012-re-module-layout-and-shared-helpers.md): RE module layout: a large `tools/mtport/<name>.py` is the public face (docstring, CLI, re-exports) of `<name>_analysis` / `<name>_doc` parts, and each low-level helper (Thumb-2 decoding, function owner, data-object window, export loading, address parsing, names files, generated doc blocks) has one implementation in `armscan`, `ghidra_common`, `names` or `macho`.
- [ADR 0013](adr/0013-ghidra-analysis-without-time-limits.md): Ghidra auto-analysis has no time limits (decompiler timeouts 0, demangler one day), so the export doesn't depend on the host's speed. The non-default options are `mtport.ghidra_common.ANALYSIS_OPTIONS`.
- [ADR 0014](adr/0014-recompiler-design.md): the static recompiler: our own standard-library Thumb-2/VFP decoder with Capstone as its test oracle, the armv7 slice at its link-time addresses, generated C17 functions `void f_XXXXXXXX(mt_cpu *)` over a `restrict`-qualified CPU state with flags in C locals, the guest memory API for both memory models, native returns, the dispatch / import / SjLj interfaces of `runtime/include/maplethief/recomp/`, and the `recomp/` module layout.
- [ADR 0015](adr/0015-recompiler-snippet-suite.md): the recompiler snippet suite: one `tests/recomp/snippets/<group>/<name>.snippet` file per hand-written Thumb-2 snippet (bytes next to the assembly, start state, expected end state from the ARM ARM), stored bytes checked by Capstone everywhere and clang where available, so CI needs no ARM assembler; registers and flags not named in `[out]` must be unchanged.
- [ADR 0016](adr/0016-function-discovery.md): function discovery is recursive descent with the recompiler's decoder. Jump tables are bounded by their guarding `cmp` through a value-numbered walk back, noreturn functions come from a fixpoint, and SjLj resume addresses are internal entries. Ghidra is only a cross-check in `work/recomp/discovery-report.md`.
- [ADR 0017](adr/0017-unicorn-differential-testing.md): the differential test of real leaf functions, run as machine code in Unicorn and as recompiled C on seeded random inputs (registers, flags, VFP registers and every changed byte compared). Unicorn is GPL-2.0, so it sits in its own `difftest` dependency group that is local only, outside `test` and CI, and never ships.
- [ADR 0019](adr/0019-import-thunks-and-hle-abi.md): import ids in `nlist` order, function/data classification with a size table for data symbols, the generated descriptor / bind / thunk tables of `imports.c`, the runtime filling `mt_import_table` by name from its HLE registry, the unimplemented-import policy (`MAPLETHIEF_UNIMPLEMENTED_IMPORT`), and the iOS armv7 calling convention of `maplethief/hle/abi.h`.
- [ADR 0020](adr/0020-sjlj-exceptions.md): SjLj exceptions: the lifter finds each resume address's jump-buffer store and emits a host `setjmp` hook and the resume label there; `runtime/src/sjlj.c` implements GCC's SjLj unwinder and personality over the guest's contexts and LSDAs (`_setjmp`/`_longjmp` on Apple), registered as HLE imports; uncaught exceptions, `throw()` violations and `std::terminate` trap. The game never throws in normal play.
- [ADR 0021](adr/0021-generated-code-partition-and-build.md): the generated C is split into translation units by fixed address cells of `__text` (64 by default), so a change to one function rewrites and rebuilds one unit. Every file is written only if it changed, and `work/gen/gen.cmake` feeds the target `maplethief_gen` through `cmake/GeneratedCode.cmake` when `MAPLETHIEF_GEN_DIR` (default `work/gen`) holds it.
- [ADR 0022](adr/0022-guest-floating-point-mode.md): the guest floating-point mode is the iOS thread default FPSCR = DN | FZ (round to nearest, flush-to-zero, default NaN), fixed at compile time for VFP and NEON alike; it supersedes ADR 0014's FPSCR = 0 assumption.
- [ADR 0024](adr/0024-release-contents-and-flow.md): a release carries one own-code port kit per platform (never the game build), built locally from an annotated `vX.Y.Z[-rc.N]` tag by `scripts/release` / `scripts/release.ps1` (tag → draft → upload → publish, generated notes grouped by label, `SHA256SUMS`); the version comes from the tag through `MAPLETHIEF_VERSION` (`MapleThief --version`), and a content guard (`tools/mtport/release.py`) rejects generated code, derived files and recompiled symbols.
- [ADR 0023](adr/0023-local-ci-and-packaging.md): every CI check runs locally first: `scripts/local-ci` on the Mac (lint, both Pythons, macOS, and Linux x86_64 in the pinned container of `tools/containers/linux/`, run by `scripts/test-linux`), `scripts\test.ps1` on Windows; the release workflows package a kit with CPack (`cmake/Packaging.cmake`: ZIP via `ditto` on macOS, ZIP on Windows, TGZ on Linux) that never contains generated code or anything from `work/`.
- [ADR 0025](adr/0025-guest-memory-and-address-space.md): guest memory. One fixed layout on every host: page zero, the image at its link-time addresses, a 480 MiB guest heap and 16 MiB of guarded guest stacks, all inside a 512 MiB arena at guest 0. It is backed by a 4 GiB + guard reservation (unchecked Release code) or by the arena alone (checked code; the iOS fallback). `MAPLETHIEF_MEM_MODEL` picks `MT_MEM_CHECKED` for the generated code. The heap's bookkeeping lives on the host, and an out-of-range access traps as `MT_TRAP_MEMORY` with the guest PC.
- [ADR 0026](adr/0026-objective-c-strategy.md): Objective-C runs on a runtime over the guest's own metadata (`runtime/src/objc/`): `objc_msgSend` looks methods up in the image's classes, recompiled IMPs run unchanged, and framework classes are host classes bound to the imported class objects. The shell is not rewritten. Host overrides replace single methods, such as `+[Chartboost sharedChartboost]` → nil.
- [ADR 0027](adr/0027-process-start-up.md): process start-up. The runtime does what the kernel, dyld and crt1 did, in one sequence (`maplethief/boot.h`, `runtime/src/boot/`): map the Mach-O and read its sections and entry from it, link, create the ObjC runtime, place, bind, realize the classes, install the overrides, seal, build the kernel's stack layout and `__program_vars`, run the `__mod_init_func` constructors with dyld's arguments, then call `main` as crt1's `start` would. Each step is a milestone of a boot trace. `UIApplicationMain` hands the guest to an app lifecycle hook. Exit (with the `__cxa_atexit` handlers), stop and trap end a run by a host `longjmp`.
- [ADR 0028](adr/0028-libc-hle.md): the libc subset. Our own printf engine prints what iOS's FreeBSD `vfprintf` prints, reads guest varargs through `mt_args`, and routes `%@` to a hook for Foundation. Guest stdout/stderr go to a configurable sink, and `___stderrp` points at a guest `FILE`. `sysctl` reports a configured device (`hw.machine`, default `iPhone3,1`) and a fixed `en0` MAC for the device id. `abort`, `__assert_rtn` and malloc errors stop the guest with `MT_TRAP_ABORT`.
- [ADR 0029](adr/0029-objective-c-runtime-services.md): the ObjC runtime's services. `mt_objc_start` binds the placed class objects, adds the host class registry (`runtime/src/objc/classes.cpp`) and placeholders for imported classes nobody implements yet, loads the image and installs the overrides. `NSObject` allocates on the guest heap, keeps retain counts and host state in side tables and frees at `dealloc`. Autorelease pools are drained every run-loop turn. `+initialize`, properties, `@synchronized` (a recursive count) and the full blocks ABI are implemented. Framework classes are written against `maplethief/objc/host.h`. GameKit is emulated, so Game Center is not overridden.
- [ADR 0030](adr/0030-runtime-diagnostics.md): runtime diagnostics (`maplethief/diag.h`, `runtime/src/diag/`). The HLE call trace wraps the import table's slots (`MAPLETHIEF_TRACE_HLE`, zero cost when off), and `mt_tracef` channels (`MAPLETHIEF_TRACE`) cover other events. One unimplemented report of imports and (class, selector) pairs, with counts and first callers, is written at the end of every guest run (and at exit). An optional symbol table from `python -m recomp symbols` (`<build dir>/maplethief.sym`, loaded only through `MAPLETHIEF_SYMBOLS`) names the functions. The compile-time function-entry coverage is `MT_TRACE_ENTRY`. The crash reporter covers traps and hardware faults: guest address and region, registers, and a validated, symbolized r7 backtrace.
- [ADR 0031](adr/0031-cxx-abi-runtime.md): the C++ ABI runtime. `operator new`/`delete` use the guest heap and stop the guest when the heap is exhausted or a pointer is bad. `__cxa_pure_virtual` stops it with `MT_TRAP_PURE_VIRT` (16) and a crash report. The `type_info` vtables are guest data: offset-to-top, then slots that only trap if the guest calls them. The runtime knows each vtable's address, so a vptr names its type_info class, and the host runs GCC 4.2's `__do_catch`/`__do_upcast` over guest memory. That matcher is the SjLj personality's `can_catch`, which now also adjusts the caught object to the base subobject (a change to ADR 0020). No game code uses RTTI and nothing inlines `dynamic_cast`.
- [ADR 0032](adr/0032-corefoundation-object-model.md): CoreFoundation. CF objects are guest ObjC objects of host classes (`__NSCFString`, `__NSCFData`, `__NSCFNumber`, `__NSCFType`, …), so toll-free bridging is literal and Foundation (#49) adds NS methods to the same classes. String text is host UTF-16 state; data bytes are a guest block. The 367 `__cfstring` literals are `__NSCFConstantString` objects in place. Encodings include EUC-KR and CP949 from a generated KS X 1001 table, and Mac OS Korean as EUC-KR. Resources are read from the extracted `.app` (`MAPLETHIEF_BUNDLE_DIR`) with exact case and `.lproj` localizations. The platform layer drives the main run loop one turn at a time (`mt_runloop_run_once`: pool, per-turn sources, due timers, the offline stubs' deliveries, then GCD's main queue; it returns when the loop next has work). CF misuse stops the guest with `MT_TRAP_ABORT`.
- [ADR 0033](adr/0033-gcd-worker-threads-and-main-queue.md): GCD (`maplethief/gcd.h`, `runtime/src/gcd/`). Global queues run on host worker threads, each with its own `mt_cpu` and guest stack, but only one guest thread runs at a time: the main thread hands a baton to one worker until its block ends or blocks, in a deterministic order, and exchanges the per-thread runtime state (SjLj, autorelease pools) at each handoff. So the rest of the runtime stays single-threaded and `dmb` stays empty. The run loop drains the main queue once per turn (`mt_gcd_drain_main`). `dispatch_once` keeps libdispatch's predicate protocol (0, 1, `~0`) for the guest's inline fast path. Waits that can never end trap with `MT_TRAP_GCD` (18). A worker that exits or traps ends the run on the main thread.
- [ADR 0034](adr/0034-offline-services.md): offline services (`runtime/src/stubs/`, `maplethief/stubs.h`). StoreKit is a host-class store that sells nothing: `canMakePayments` YES, one product per request, and every payment ends cancelled (state failed), the game's own clean path; this replaces the `canMakePayments` NO override, which left "Please Wait..." up for ever. GameKit is emulated: an always-authenticated local player, and scores and achievements saved to `gamecenter.json` in the data directory. Completion handlers and StoreKit answers run from `mt_stubs_pump` on the next run-loop turn. `CFSocketConnectToAddress` fails at once, and SystemConfiguration says not reachable.
- [ADR 0035](adr/0035-foundation-subset.md): Foundation (`runtime/src/foundation/`). Exactly the Foundation selectors live game code sends ([re/host-surface.md](re/host-surface.md), generated by `mtport.hostsurface`, checked by `objc.host_surface`) plus what the runtime's host code sends; anything else is an unrecognized selector. NSString's selectors are **host categories** on CF's bridged classes (`mt_objc_host_category`, the hook #51 added for its NSString drawing selectors; one line each in `classes.cpp`). Collections have no class clusters (host-state vectors of retained objects; fast enumeration with a mutation counter). Info.plist and the `.strings` tables are read by a bounds-checked binary-plist reader. The guest home directory maps to the data directory: saves are `<data dir>/Documents/theif0` etc.; the bundle is read-only. NSLocale answers from the configured language. Misuse raises as `MT_TRAP_ABORT`.
- [ADR 0036](adr/0036-coregraphics-and-uikit-drawing.md): CoreGraphics and UIKit drawing (`runtime/src/cg/`). Our own software rasterizer draws 8-bit premultiplied RGBA into any 32-bit CG layout: anti-aliased signed-area coverage, a clip mask, Normal/Copy/Clear compositing, linear and radial gradients, and bilinear image draws that copy exactly at 1:1. CG objects are `__NSCFType` instances with host state. `UIImage` decodes PNGs (CgBI included) with stb_image to the layout ImageIO gave. UIKit's text calls use one bundled font, NanumGothic (OFL, downloaded with a pinned hash and embedded), for every face, with synthetic bold, rasterized by stb_truetype. NSString's drawing selectors are a host category (`mt_objc_host_category`) on #49's NSString.
- [ADR 0037](adr/0037-uikit-host-classes-nib-and-compositor.md): UIKit (`runtime/src/uikit/`, `maplethief/uikit.h`). The UIKit classes the game reaches are host classes with exactly its selectors (checked by `objc.host_surface`), one host `View` per view with model values. `UIApplicationMain` (`mt_uikit_app_main`) reads `MainWindow.nib` with a hardened NIBArchive reader and decodes it as UIKit did (class swappers, proxies, `-initWithCoder:` through a host `UINibDecoder`, outlets), sends the delegate its launch callback with the nib's window, then runs the main run loop with a host turn hook. Touches are queued by the host and delivered on the guest thread each turn (hit testing, UIControl tracking, scroll-view dragging and paging). UIView animations keep presentation values beside model values. The compositor draws the view tree with #51's rasterizer onto the 480 × 320-point landscape screen, with the `CAEAGLLayer` view as a GL slot (a given frame, or transparent for an overlay over the platform's GL picture).
- [ADR 0038](adr/0038-gl-recording-eagl-silent-audio-boot-to-first-frame.md): boot to the first GL frame (`runtime/src/gles/`, `runtime/src/audio/`, `maplethief/gles.h`, `maplethief/audio.h`). The 31 GL imports are recorded in three layers: decode into an `mt_gles_cmd`, a state tracker that answers every query the game makes (names, `glIsTexture`, framebuffer status, renderbuffer size) truthfully and counts misuse, and a command hook where #56 executes. `EAGLContext` is a host class: the renderbuffer gets the `CAEAGLLayer`'s bounds and drawable properties, and `presentRenderbuffer:` hands an `mt_gles_frame` to a present hook (#58), which can end the run. The first present after a draw call is the boot milestone `first-frame`. OpenAL, the audio session, ExtAudioFile, `AVAudioSession` and `AVAudioPlayer` are silent but keep their state and error rules until M6 replaces them. `CC_MD5`/`CC_SHA1` are real.
- [ADR 0039](adr/0039-rendering-backend-software-rasterizer.md): the rendering backend is `mt_gfx` (`runtime/src/gfx/`, `maplethief/gfx.h`), a deterministic software rasterizer behind a draw interface: #56's GLES layer turns each `glDrawArrays` into one self-contained `mt_gfx_draw` (clip-space vertices with s, t, constant colour, texture handle, blend factors, viewport). Clipping, 28.4 snapping, integer edge functions with the top-left rule, 1-pixel lines by the diamond-exit rule (#121), perspective-correct texture coordinates, nearest/bilinear with 8-bit weights, `GL_MODULATE` and all GL ES 1.1 blend factors in integer arithmetic, compiled without FP contraction, so golden images match exactly on every OS and CPU. Targets have a logical size and an integer internal scale; a host hook can replace uploaded textures by content hash with k× images (both seams for M10). Frames are presented as one SDL_Renderer streaming texture (`ABGR8888`). A GPU backend (SDL3 GPU) sits behind the same interface ([ADR 0060](adr/0060-gpu-rendering-backend.md)).
- [ADR 0040](adr/0040-gles-fixed-function-pipeline.md): GL ES 1.1's fixed-function pipeline (`runtime/src/gles/fixed.cpp`) is built into the runtime and always on: decode → tracker → pipeline (only for calls the tracker accepted) → trace → the command hook as an observer. Matrix stacks with values (`GLfixed` = v / 65536; `glRotatex` with an exact degree reduction and series, no libm), client arrays read from guest memory at `glDrawArrays` after a range check against the mapped regions, one `mt_gfx` draw per `glDrawArrays` into the target of the bound framebuffer's colour attachment. Texture objects own `mt_gfx` textures, renderbuffers with EAGL storage own `mt_gfx` targets at `mt_gles_config.render_scale`; `mt_gles_frame.target` is the presented one. GL's error flag is kept (`mt_gles_get_error`), misuse is logged once per kind (then at 10×, 100×, …); `MAPLETHIEF_GL_TRACE_FILE` writes every call, decoded, with each draw's outcome.
- [ADR 0041](adr/0041-texture-formats-and-premultiplied-alpha.md): the game uploads only `GL_RGBA`/`GL_UNSIGNED_BYTE` from three call sites: the PNG loader `FUN_00009534` (a premultiplied, flipped, zero-padded power-of-two CoreGraphics buffer, up to 1024 × 512) and the text texture `FUN_00007ad8` (512 × 32, texels `(a, a, a, a)`). Texels are kept as uploaded, with no un- or re-premultiplying: the game blends them with `GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA`, so the device's darkened edges are kept. `mt_gfx` converts all seven GL ES 1.1 format/type pairs as `GL_MODULATE` reads them. The loader's premultiplication `round(c × a / 255)` was checked against Apple's CoreGraphics on every shipped PNG; there is no colour management, as on iOS 4. Clipping uses a 16w guard band for x and y, bounded by the viewport, so 1:1 sprites over the screen's edge sample texel centres. `runtime.launch_real` checks every pixel of every 1:1 sprite against the device's modulate-and-blend. The GL trace names each upload's call site.
- [ADR 0042](adr/0042-frontend-game-loop-and-presentation.md): the frontend runs the game (`platform/src/game.{h,cpp}`, `present.{h,cpp}`, the library `maplethief_frontend`). `MapleThief` links `maplethief_gen` only when the build has it and then boots the game by default: the bundle from `--bundle`, `MAPLETHIEF_BUNDLE_DIR` or the build's `work/ipa/Payload/MapleThief.app`, the armv7 slice of its fat executable (a bounds-checked fat header walk), the data directory from `MAPLETHIEF_DATA_DIR` or `SDL_GetPrefPath`. Without generated code it stays the placeholder shell, so CI, `platform.smoke` and the release kits are unchanged. One thread: the guest runs on the main thread; the GL present hook copies the presented target (opaque) and presents the window at once (the loading screen animates inside one run-loop turn), and the UIKit turn hook pumps SDL, presents for events, animations and a 0.25 s refresh, and waits until the run loop's next wake. Presentation: `mt_uikit_composite` (full) at 480 × 320 × render scale → an `ABGR8888` streaming texture → `present_rect()`, the one seam for #59 (today an aspect fit with black bars in the drawable's pixels, nearest). Nothing clears a target, so contents are retained; the game draws landscape directly, so nothing is turned. `--render-scale`, `--frames` (read-back check), `--capture`, `--tap`.
- [ADR 0043](adr/0043-scaling-modes-mouse-mapping-and-settings-file.md): scaling (`platform/src/scaling.{h,cpp}`, pure) replaces `present_rect()`'s policy. Modes `integer` (default: the largest whole multiple k of the 480 × 320 screen points, whatever the render scale, nearest; under 1× the fit), `fit` (nearest), `smooth` (bilinear) and `sharp` (`SDL_SCALEMODE_PIXELART`), with bars in a configurable border colour. The placement is always in drawable pixels (HiDPI). Its inverse, `window_to_screen` / `window_point_to_screen` (window points × the window's density → drawable pixels → 480 × 320 screen points, `inside` false over the bars), is what M7's mouse input (#65) calls; `--tap` goes through it. The frontend's first settings file, `settings.ini` in the data directory (`platform/src/settings.{h,cpp}`): `key = value` lines, `#` comment lines, keys `scale_mode`, `border_color`, `render_scale`, and since #64 `master_volume`, `music_volume`, `effects_volume` (0–100) and `mute_unfocused` (on/off); unknown keys and bad values are logged and ignored; the command line (`--scale-mode`, `--border-color`, `--render-scale`, `--master-volume`, `--music-volume`, `--effects-volume`, `--mute-unfocused`) overrides it. `serialise_settings`/`save_settings` write it back keeping comments and unknown lines (`--save-settings`). `--window WxH`.
- [ADR 0044](adr/0044-virtual-clock-and-device-golden-screens.md): scripted runs and the device golden screens. `MapleThief --fixed-step MS` puts one virtual clock (`platform/src/clock.{h,cpp}`) behind every clock the guest reads (`mt_libc_config.clock`: `gettimeofday`, `CFAbsoluteTimeGetCurrent`, the run loop, UIKit; `mt_gcd_config.clock`/`sleep_until`), starting at 2025-01-01T00:00:00Z (`GetTimeMs` 522,812,416, clear of its 2³¹ jump; the random seed is fixed) and advanced by MS per run-loop turn, never waited for; `--shot T,NAME` writes the composited 480 × 320 screen at virtual time T. A scripted run is identical every time, in Debug and Release, on arm64 and x86_64. `tests/golden/device_screens.json` lists seven screens (title = the main menu with its promo banner, main menu, the intro's speech box with its `GL_LINES` border, NPC dialog, first map, popup, character select) with taps, device steps, masks and tolerances; `python3 -m mtport.devicegolden` (CTest `platform.device_golden`, real assets) compares each with our recorded render (`work/golden/ours/`, exact) and the device screenshot (`work/golden/device/`), normalised by `mtport.goldencmp` (portrait turned with ADR 0037's mapping, Retina 2 × 2 averaged, 4-inch letterbox cropped).
- [ADR 0045](adr/0045-audio-mixer-and-output.md): audio is a deterministic mixer in the runtime (`runtime/src/audio/mixer.{h,cpp}`), pulled through `maplethief/audio.h`: `mt_audio_render` (44,100 Hz stereo float), buses master/music/effects (`mt_audio_set_gain`, `mt_audio_set_muted`), `mt_audio_get_output_stats`, `mt_audio_note_late`. OpenAL is real: `alBufferData` copies the guest's PCM (MONO8/16, STEREO8/16) into a shared host `Pcm`, `alSourcePlay` (re)starts the source's voice, which steps through it with a 32.32 position and integer linear interpolation (strict FP: the same bytes on every host), `alListenerf(AL_GAIN)` scales the effects, a suspended or released context pauses them; `alcGetProcAddress` answers NULL (the one name the game asks for, `alBufferDataStatic`, is on a dead path). Music voices pull a `mix::MusicStream` in blocks of 4,096 frames under the mixer's one lock (dr_mp3 behind `AVAudioPlayer`: ADR 0046). `platform/src/audio_out.{h,cpp}`: one `SDL_OpenAudioDeviceStream` (F32, 2, 44,100) whose callback renders what SDL asks for, late callbacks counted, no device = silent; `--no-audio`; `--audio-capture FILE.wav` renders the mix up to the run's time after every turn (byte-identical under `--fixed-step`); `--audio-test-tone`. Addendum (#64): AudioSession keeps the device's error codes and never calls the interruption listener; `AudioServicesPlaySystemSound(0xFFF)` calls `mt_audio_set_vibrate_hook`'s function (the gamepad's rumble, ADR 0053); `settings.ini`'s volumes set the buses at start-up and `FocusMute` mutes while the window is unfocused (`mute_unfocused`, never under `--audio-capture`). Addendum (#124): M6's exit criteria are checked through the game's own `CMSoundPlayer::Play` and `CStateGame::PlayMapBGM` (`audio.game_sounds`, `audio.game_map_music`, real assets); `--seconds S` ends a run after S seconds (a soak's time limit), and the exit log compares the device stream's running time with the audio it pulled.
- [ADR 0046](adr/0046-avaudioplayer-mp3-streams-and-loop-points.md): `AVAudioPlayer` plays an `Mp3Stream` (`runtime/src/audio/mp3_stream.{h,cpp}`): dr_mp3 (scalar, strict FP: the same samples on every host) streaming from the file's bytes in host memory as the music voice pulls them. A pass is Apple's decoder timeline, measured against ExtAudioFile: MPEG frames × samples per frame, dr_mp3's output from frame 529 on (the decoder delay dropped) and 529 frames of silence at the end; it loops whole, encoder delay and padding included, as on the device. `play`/`stop` (exact frame kept)/`isPlaying`/`setVolume:`/`setNumberOfLoops:` (negative for ever)/`setCurrentTime:` (⌊t × rate⌋, through `mix::music_edit`); nil for a file without MP3 audio; dealloc removes the voice.
- [ADR 0047](adr/0047-touch-input-mouse-and-fingers.md): touch input. `platform/src/input.{h,cpp}` (`Input`) turns SDL events into `mt_uikit_touch` calls, and every polled event goes through it.
  - The left mouse button is one touch (down Began, motion while held Moved, up Ended). The right button is optionally a second touch at a fixed screen point (`right_touch = X,Y | off`, `--right-touch`).
  - Direct touch screens are multi-touch, one finger id per SDL finger. Trackpads and SDL's synthetic mouse-from-touch, mouse-from-pen and touch-from-mouse events are dropped (the pen since #73).
  - A press that begins over the bars is dropped; a drag that leaves the image is clamped to its edge.

  - `Input::touch(source, id, …)` is the shared entry point for virtual touches (#67's gamepad), and the activity listener tells touch from non-touch input (#71).
  - `--tap` is a left click handed to the same event handler.
  - In the runtime: `tapCount` (0.35 s, 25 points), `UIEvent touchesForView:`/`touchesForWindow:`, and a turn's queued moves of one finger merged into one.
- [ADR 0048](adr/0048-gamepad-actions-and-delivery.md): gamepads as key pad actions.

A step is a batch of pad BOOL setters (`setOnLeftKey:` …, then `checkCrossKeyPad`) while the pad is live, so `SkyCanvas::Tick`'s priority and chords stay the game's, or one `Clet_HandleEvent(2|3, code, 0)`. A release goes the way its press went.

- [ADR 0051](adr/0051-controller-focus-navigation.md): controller navigation of the UIKit screens.

- [ADR 0052](adr/0052-hiding-the-on-screen-key-pad.md): hiding the on-screen key pad (`platform/src/keypad_hide.{h,cpp}`, `KeypadHider`).

The window comes from `SDL_CreateWindow` with #73's flags (fullscreen on iOS); `GfxBackendHost` makes its renderer.
- [ADR 0060](adr/0060-gpu-rendering-backend.md): a GPU rendering backend on SDL3 GPU behind `mt_gfx`'s draw interface (`runtime/src/gfx/gpu/`, `maplethief/gfx_gpu.h`, library `maplethief_gfx_gpu`).
  - The seam: mt_gfx has a backend slot (`gfx_internal.h`, `class Backend`). With none installed (the default) everything is the software rasterizer, unchanged and the reference. Installed, `mt_gfx_submit` hands each validated draw to it; `mt_gfx_target_cpixels`, `mt_gfx_target_pixels` and `mt_gfx_target_fill` sync first (read back, mark the CPU newer, overwrite); a texture's upload or destroy flushes the queued draws that use it. Nothing above `gfx.h` changes (`mt_gfx_backend_name()` is the only addition).
  - The GPU backend expands strips, fans and loops to lists, batches consecutive draws with the same target, pipeline, texture, sampler, viewport and scissor, and flushes at `mt_gfx_end_frame`, at a CPU read and before a queued texture changes. It snaps vertices to mt_gfx's 1/16-pixel grid, nudges line ends and texture coordinates onto mt_gfx's tie-breaks, and matches the software rasterizer within ±2 per channel on all but 0.5% of the pixels (`gfx_gpu.*`, `platform.gpu_compare`, local only: CI has no GPU).
  - Shaders are HLSL in `runtime/src/gfx/gpu/shaders/`, compiled offline by `scripts/build-shaders` (a pinned container: DXC → DXIL and SPIR-V, `spirv-cross` → MSL, `spirv-val`, a descriptor-set check) into the committed `shaders_compiled.h` with source stamps (`shaders.stamps` fails on a stale header).
  - The frontend (`platform/src/gfx_backend.{h,cpp}`): `gfx_backend = software | gpu` (`settings.ini`, `--gfx-backend`). `gpu` makes an SDL GPU device, installs the backend and gives the window SDL's GPU renderer on the same device; without a device it logs "the GPU backend is not available" and stays software. The present stage's passes (`PresentPass`, `Presenter::set_render_state`) draw the screen image through a library fragment shader (`present_copy.frag`, the identity and the template for #88's filters). Since [ADR 0068](adr/0068-gpu-presentation-without-read-back.md) (#130) the frames stay on the GPU.
- [ADR 0062](adr/0062-optional-gapless-music-loops.md): optional gapless music loops (#125). `gapless_music` in `settings.ini` / `--gapless-music`, off by default, sets `mt_audio_set_gapless_music` before the boot. An `AVAudioPlayer` opened with it on gets an `Mp3Stream` trimmed to the frames from its file's first to its last one that is not exactly 0, on a trimmed timeline (`seek`, `setCurrentTime:`, `stop`'s frame and the loop all use it). A desktop minimise resigns the delegate (`applicationWillResignActive:`, the game's `Clet_Pause`) and the restore makes it active again; on iOS `WILL_ENTER_BACKGROUND` and `DID_ENTER_FOREGROUND` do (the app events through an `SDL_AddEventWatch`), one message per change whatever SDL's mix of events. The fixed-step mode takes only scripted events (`--minimise T,S`, `--background T,S`, `--quit T`) and jumps the virtual clock over the hidden time.

- [ADR 0066](adr/0066-shader-filters-and-text-at-the-render-scale.md): shader filters and the game's text at the render scale.
  - `filter = none | xbr | crt | lcd` (`settings.ini`, `--filter`; game only, default `none`). Each filter is a present pass (`present_xbr.frag`, `present_crt.frag`, `present_lcd.frag`) over the scale mode's rectangle: xBR-style 45° edge smoothing, CRT scanlines with an aperture mask, an LCD cell grid. They read texels with integer loads and take one uniform block (`PresentSizes`: the image's texels and the rectangle's pixels) that the Presenter pushes before each draw. A filter needs SDL's GPU renderer for the window, which the frontend asks for whatever `gfx_backend` is (on the software path, on a device of its own). Without one (the dummy driver, no GPU) it logs that and draws with the scale mode's own filter; there is no CPU path. Under a filter, `--frames`' read-back check judges xbr as a blend of neighbouring texels and crt/lcd by the bars only. GPU time per pass on the Mac (M4): at most 0.73 ms at 3840 × 2160 (crt), well under 1 ms at 1080p and 1800p (`gfx_gpu.present filters: *`).
  - `hd_text = on | off` (`--hd-text`, default off; `maplethief/cg.h`, `runtime/src/cg/hires_text.cpp`). At render scale N > 1, every `-drawAtPoint:withFont:` into a bitmap context over guest memory (TextCache_DrawText's 512 × 32 buffer) is drawn again into the context's N× shadow. `mt_cg_text_replace`, installed as mt_gfx's replacement hook, hands that shadow to the `glTexImage2D` whose content hash is the 1× pixels the shadow was last drawn over. A buffer changed after the draw no longer matches and is uploaded as it is. The shell's UIKit text is already composited at N×.
- [ADR 0068](adr/0068-gpu-presentation-without-read-back.md): GPU presentation (`platform/src/gpu_screen.{h,cpp}`, `GpuScreen`). With mt_gfx on the GPU and SDL's GPU renderer for the window, the GL frame no longer comes back to the CPU.
  - At `presentRenderbuffer:` the target's texture (`mt_gfx_gpu_target_texture`, which now also uploads CPU-newer pixels) is copied GPU to GPU. This keeps ADR 0042's tear-free copy.
  - Each present composites UIKit's views in the compositor's overlay mode and uploads them only when they changed. The Presenter's screen texture is then a render target: opaque black, the GL copy in the GL view's rectangle (colour only), the overlay premultiplied over it. The Presenter draws that texture as before, so the scale modes and #88's filters are unchanged.
  - Shots, `--shot-gl`, `--capture`'s first-lit tracking and the `--frames` check download on demand. The check also compares the GPU's screen against the CPU's full composite within ADR 0060's tolerance. mt_gfx's `readbacks` stays 0.
  - `MAPLETHIEF_GPU_READBACK=1` keeps the read-back path. The frame-time log line is `game: frame time: ... ms per window frame`.
  - The remap overlay (#70, addendum): `GpuScreen::compose_over` draws it over UIKit's premultiplied layer and composes again, with no guest call (`run_remap` redraws while it holds the turn). The next compose is without it, so shots are too. `Canvas` blends alpha "over" (opaque images unchanged). `run_remap` keeps the lifecycle's gate: nothing drawn while hidden, the messages delivered after the overlay closes, a quit ends the hold.
- [ADR 0069](adr/0069-guest-function-hooks.md): guest function hooks: the host replaces or wraps a recompiled function.
  - The recompiler (`recomp/hooks.py`, `HOOKED`) lifts each listed function as its unchanged body, `static f_X_original`, plus `f_X`, which is only `MT_FN_HOOK(0xXu, f_X_original)`.   - `returns=True` marks a function that never returns in the original but may with the hook (`OpenPortalURLAndExit` `0x22955`, `exit(1)`). Discovery still records it as noreturn, but its callers' flow goes on after the call (`discover(image, may_return=...)`).
  - The runtime's registry (`maplethief/hooks.h`, `runtime/src/hooks/`): `mt_hook_register(fn, handler, user, enabled)`, `mt_hook_set_enabled` at run time, statistics, trace `hooks`. Only `MT_HOOK_FN_*` functions are accepted. A handler is entered like an HLE function (ADR 0019) and replaces (`MT_HOOK_HANDLED`), wraps (calls `call->original(cpu)`) or passes (`MT_HOOK_PASS`).

The frontend's temporary `--portal-exit quit|stay` (default `quit`, the original) switches it until the settings registry (#144) puts it under the Enhanced preset.

## Goals and constraints

- Run MapleStory Thief Edition 1.5 natively on **macOS** (universal arm64 + x86_64), **Windows 10/11 x64** and **iOS 16+ arm64**, with **Linux / Steam Deck** where it's cheap.
- Keep game logic **faithful**: same timing, same RNG, same save semantics. Enhancements are opt-in and layered on top (M10).
- **Controller support** as a first-class input path, not as fake touches where avoidable.
- **Build from your own copy.** The repo contains no derived game content. The build reads `original/*.ipa` and produces everything else locally.

## Approach: hybrid static recompilation

```
original/MapleThief-1.5.ipa
        │  scripts/bootstrap (verify + extract + split fat binary)
        ▼
work/ipa/…/MapleThief.app ─────────────► tools/ asset pipeline ──► assets-out/ (PNG, JSON, disasm)
        │ armv7 slice
        ▼
recomp/  (loader → decoder → function discovery → lifter → C output; ADR 0014)
        │
        ▼
work/gen/*.c  (one C function per guest function, ~2,655)
        │
        ▼
runtime/  (HLE: memory, loader, libc/C++/CF/Foundation, ObjC, GCD, GLES1, OpenAL, …)
        │
        ▼

        │
        ▼
build/<preset>/platform/MapleThief (.app / .exe / iOS app)
```

### 1. Static recompiler (`recomp/`)

Ahead-of-time translation of the **armv7** slice (Thumb-2 + the single ARM entry stub) into C, in the style of N64Recomp / XenonRecomp / ReXGlue. The recompiler is standard-library Python and runs only on the build machine ([ADR 0002](adr/0002-language-and-toolchain.md)). The design is settled in [ADR 0014](adr/0014-recompiler-design.md):

- **Input:** the thin armv7 Mach-O, mapped at its link-time addresses (slide 0), so PC-relative addresses and literal-pool loads from the immutable `__TEXT` fold into constants. The armv6 slice is not lifted: it has as much conditional execution, none of the RE work applies to it, and it stays available as a second oracle (#41). `recomp/loader.py` builds on `mtport.macho` ([#31](https://github.com/armaatus/maplethief-port/issues/31)): segments and sections with their file mapping, `LC_FUNCTION_STARTS`, the entry point, the 2 init functions, rebases and the 1,272 binds, the 333 imports with their stub and pointer addresses, and the ObjC section ranges. `python -m recomp load` writes them to the loader manifest `work/recomp/loader.json` (schema in `recomp/loader.py`), which the runtime's loader reads.
- **Decoding:** our own Thumb-2/VFP decoder from the ARM ARM's tables (`recomp/decode/`), with explicit IT state, plus an A32 decoder for the entry stub's instruction classes (`decode/arm.py`, [#33](https://github.com/armaatus/maplethief-port/issues/33)). Capstone is its oracle in tests: identical text on all 330,052 instructions of `__text`, on every 16-bit encoding, on 60,000 random 32-bit ones per CI run and on random words of every A32 class. `decode/neon.py` decodes the Advanced SIMD classes the binary uses (381 instructions, [#34](https://github.com/armaatus/maplethief-port/issues/34)).
- **Function discovery:** recursive descent with our own decoder from the 2,655 `LC_FUNCTION_STARTS` seeds plus ObjC IMPs, vtable slots, init functions and call targets (`recomp/discover.py`, [ADR 0016](adr/0016-function-discovery.md), [#32](https://github.com/armaatus/maplethief-port/issues/32)). It resolves jump tables from their guarding `cmp` (184 `tbb`/`tbh` and 16 SjLj branch tables), stops at noreturn calls (imports plus a whole-program fixpoint), marks literal pools and tables as data, and enters the SjLj landing code at its resume address. `python -m recomp discover` writes `work/recomp/functions.json` (blocks, edges, mode, tables, calls) and `work/recomp/discovery-report.md`. The report cross-checks the result with the Ghidra export, which is never an input: 0 unexplained differences, and every table target agrees.
- **Lifting:** each guest function becomes `void f_XXXXXXXX(mt_cpu *MT_RESTRICT cpu)`, named after its function pointer (Thumb bit set). Each instruction becomes a few C statements, IT and other conditional instructions an `if`, and branch targets labels. One lifter module per instruction class lives in `recomp/lift/`; a form with no lifter becomes a trap at its address and a coverage entry. `python -m recomp census` ([#33](https://github.com/armaatus/maplethief-port/issues/33)) counts every instruction form and its trapped instances in `work/recomp/census.json`. No instruction of the binary traps (all 2,655 functions lift cleanly, [#34](https://github.com/armaatus/maplethief-port/issues/34)), and each of its 189 integer and 55 VFP/NEON forms has a snippet test.
- **CPU state:** `mt_cpu` (`runtime/include/maplethief/recomp/cpu.h`) holds `r[16]`, `cpsr`, `fpscr`, `d[32]` (s registers are the halves of d0–d15), the guest memory base and size. Generated code accesses it directly through a `restrict` pointer, so the state is exact at every call, return, trap and SjLj resume while the host compiler still keeps registers in host registers between calls. N, Z, C and V are C locals computed only if the function reads them; the recompiler proves per function that no flag is live into a function or across a call.
- **Floating point:** one fixed guest mode, the FPSCR iOS gives every thread and the binary never changes: round to nearest, flush-to-zero, default NaN (`0x03000000`, [ADR 0022](adr/0022-guest-floating-point-mode.md)). That is also NEON's standard mode, so VFP and NEON f32 lanes share the `vfp.h` helpers. They compute with host IEEE arithmetic (contraction off) and apply the ARM rules explicitly: input and output flushing decided on the exact value, the default NaN, and saturating float→integer conversions with NaN → 0, all without C undefined behaviour, so every host gives the same bits.
- **Memory model:** guest address + `cpu->mem`, through `memcpy`-based `MT_LD*`/`MT_ST*` macros that carry the guest PC. One API, two models: a 4 GiB reservation with no checks, or bounds checks against the 512 MiB arena that trap with the guest PC (Debug builds, tests, iOS). The runtime side is `maplethief/memory.h` ([ADR 0025](adr/0025-guest-memory-and-address-space.md), [#42](https://github.com/armaatus/maplethief-port/issues/42); see section 2).
- **Calls:** `bl`/`blx imm` set `lr` and call the target's C function; returns are C returns (checked against `lr` at entry in debug builds); `b` to another function is a guaranteed tail call under clang (`MT_TAILCALL`). Indirect calls and jumps (`blx reg`, `bx reg`, vtables, ObjC IMPs, function pointers, blocks) go through `mt_dispatch`, the **guest function pointer → host function table** (`work/gen/dispatch.c`: every function, keyed by pointer with the Thumb bit, plus a 16-byte bucket index; then the import thunks of `imports.c`; the lookup is `runtime/src/recomp/dispatch.c`). A miss traps with `MT_TRAP_NO_FUNCTION` and is reported with the site, the function it is in, `lr`, the reason (wrong instruction set, misaligned, mid-function, null) and the r7 backtrace; there is no interpreter fallback ([#35](https://github.com/armaatus/maplethief-port/issues/35), ADR 0014 addendum).
- **Imports** ([ADR 0019](adr/0019-import-thunks-and-hle-abi.md), [#36](https://github.com/armaatus/maplethief-port/issues/36)):
  - **Ids and classification.** All 333 imports have an id, their `nlist` index. 222 are functions: called through a stub, or reached only through a pointer. 111 are data: ObjC classes, constants and block isas.
  - **Calls.** A call through a `__symbolstub1` stub is `MT_CALL_IMPORT(id)`, which goes through `mt_import_table`.
  - **The generated tables.** `work/gen/imports.c` holds a descriptor per import (flags, guest code address, data size and alignment), every bind (slot, id, addend), and one thunk per function import, so that a guest pointer to an import is callable through the dispatch table.
  - **Start-up.** The runtime (`runtime/src/hle/`) fills the table by name from its HLE registry. Every other slot gets the default handler, which logs the name and the caller (`lr`), then stops or returns 0, per `MAPLETHIEF_UNIMPLEMENTED_IMPORT=stop|continue|trace`. It also places zeroed data objects through the memory model's allocator, then writes the binds.
  - **Calling convention.** HLE functions read their arguments with the iOS armv7 rules in `maplethief/hle/abi.h`: soft-float, 64-bit values 4-byte aligned and allowed to split across r3 and the stack, structures larger than 4 bytes returned through r0.
- **Exceptions:** SjLj (205 functions, [ADR 0020](adr/0020-sjlj-exceptions.md)). Where the guest stores a resume address into a function context's jump buffer, the generated code takes a host `setjmp` (`MT_SJLJ_SETJMP`, found by `recomp/lift/sjlj.py`) and the runtime's unwinder (`runtime/src/sjlj.c`: `_Unwind_SjLj_*`, the personality reading the guest's LSDAs, the ObjC catch helpers) `longjmp`s back to the resume label with the guest state in `mt_cpu`. `python -m recomp exceptions` writes the context census, `work/recomp/exceptions.json`. No guest code starts an exception, so in normal play the landing pads never run; an uncaught exception or `std::terminate` traps.
- **Output:** C17 in `work/gen/` (`mt_gen.h`, `fn_NNN.c`, `imports.c`, `dispatch.c`, `gen.cmake`), never committed. A function goes into the unit of the fixed `__text` address cell that holds it (64 cells by default), and files are written only when they change, so a change to one function rebuilds one unit ([ADR 0021](adr/0021-generated-code-partition-and-build.md), [#38](https://github.com/armaatus/maplethief-port/issues/38)). The full Release build of the 42 MB of C takes about 7 s on an Apple M4 with 10 cores, bound by the four largest functions (0.8–1.3 MB of C each). Reports go to `work/recomp/`. `python -m recomp` is the command line (`all` runs load, discover and lift, then writes the coverage report); `recomp.snippet.lift_snippet` is the interface of the snippet tests ([#39](https://github.com/armaatus/maplethief-port/issues/39)).
- **Coverage:** `python -m recomp coverage` ([#40](https://github.com/armaatus/maplethief-port/issues/40), ADR 0014 addendum) compiles every generated unit with the host compiler (the build's flags plus warnings as errors) and charges each error to its function. It writes `work/recomp/coverage.md` and `coverage.json`: per function and per #10 tag, discovered / lifted cleanly / compiled, and every function that is not clean with its stage, address and reason. `lift` and `all` write the same report without compiling (`--compile` to measure it), and every run ends with its summary line. All 2,655 functions are discovered, lifted cleanly and compiled (target 99%).

The ADR's prototype lifts the whole binary in 2.3 s; 89.5% of the functions lift with no problem before any of the later M3 children, and the 34 MB of C passes clang `-Wall -Wextra -Werror -Wpedantic` and compiles at `-O2` in 17 s on one core.

### 3. Platform layer (`platform/`)

- C++20 on **SDL3** (3.4.x, linked statically on every platform; [ADR 0003](adr/0003-dependencies.md)) for windowing, input, gamepads, audio device, file paths (`SDL_GetPrefPath`) and the main loop on every OS.
- **The game ([ADR 0042](adr/0042-frontend-game-loop-and-presentation.md)):** with the generated code in the build, `MapleThief` boots the recompiled game from the extracted bundle (`platform/src/game.{h,cpp}`) and runs it on the main thread: `mt_process_run` with `mt_uikit_app_main`, the GL present hook and the UIKit turn hook pumping SDL's events, presenting and waiting for the run loop's next wake. The app lifecycle reaches the delegate from the turn hook, and a minimised window (the background on iOS) is not presented while the guest waits ([ADR 0063](adr/0063-app-lifecycle-background-and-minimise.md)). Closing the window sends `applicationWillTerminate:`, then ends the run from the turn hook (`MT_PROCESS_STOPPED`). Without generated code (CI, the release kits) it is the placeholder shell.
- **Graphics backend ([ADR 0039](adr/0039-rendering-backend-software-rasterizer.md), [ADR 0042](adr/0042-frontend-game-loop-and-presentation.md)):** the game's GL ES 1.1 renders on the CPU with `mt_gfx` (runtime). The platform layer (`platform/src/present.{h,cpp}`) copies each presented renderbuffer, composites the screen with UIKit's views over it (`mt_uikit_composite`, full mode, 480 × 320 × render scale), uploads it as one SDL streaming texture (`SDL_PIXELFORMAT_ABGR8888`) and draws it with `SDL_RenderTexture` at `place()` of the drawable's pixel size ([ADR 0043](adr/0043-scaling-modes-mouse-mapping-and-settings-file.md), `platform/src/scaling.{h,cpp}`): integer nearest by default, or fit nearest, smooth or sharp, between bars of the border colour; SDL_Renderer picks Metal, D3D, Vulkan or GL per platform. `MapleThief --gfx-prototype` shows `mt_gfx`'s prototype scene (`platform/src/gfx_prototype.cpp`). With `gfx_backend = gpu` ([ADR 0060](adr/0060-gpu-rendering-backend.md), `platform/src/gfx_backend.{h,cpp}`) `mt_gfx` draws on SDL3 GPU (Metal, D3D12, Vulkan) behind the same interface, the window gets SDL's GPU renderer on the same device, and the Presenter can draw the screen through a present pass (a fragment shader from the library); the default stays the software rasterizer. On that path the GL frame stays on the GPU ([ADR 0068](adr/0068-gpu-presentation-without-read-back.md)): a GPU copy of it under UIKit's views (the compositor's overlay mode, uploaded as a second texture) is composed into the Presenter's screen texture, and nothing is read back per frame. The shader filters (`filter = xbr | crt | lcd`, [ADR 0066](adr/0066-shader-filters-and-text-at-the-render-scale.md)) are such passes; they ask for SDL's GPU renderer for the window with either backend.
- **Audio output ([ADR 0045](adr/0045-audio-mixer-and-output.md)):** `platform/src/audio_out.{h,cpp}` opens the default playback device with `SDL_OpenAudioDeviceStream` (`SDL_AUDIO_F32`, 2 channels, 44,100 Hz; SDL converts to the device) paused, resumes it at the first run-loop turn, and renders exactly the frames its callback asks for with `mt_audio_render`; a callback more than 1.5 × the previous delivery late goes to `mt_audio_note_late`. No device is not an error. `--no-audio` opens none, nor does `--fixed-step`; `--audio-capture FILE.wav` writes the mix as 16-bit stereo instead, up to the run's (virtual) time after every turn, the remainder carried. `MapleThief --audio-test-tone` plays 440 Hz for 1.5 s through the device (CTest `platform.audio_tone` on the dummy driver).
- iOS: SDL3 UIKit integration, safe-area aware layout, MFi/Xbox/PS controllers via GameController.framework (through SDL).
- Linux / Steam Deck ([ADR 0065](adr/0065-linux-and-steam-deck-build.md)): per-OS files in `platform/linux/` (the static C++ runtime, its portability test, the launcher). The game folder from `scripts/linux-game` runs on glibc 2.39+, natively on the Deck as a non-Steam game ([docs/linux-and-steam-deck.md](linux-and-steam-deck.md)).

## Later, optional: decompilation track

Once the game is fully playable via recompilation, hot or interesting engine systems (e.g. `CMMap` rendering, `CHero` physics, the script VM) can be **progressively replaced with hand-written C++** that is verified against the recompiled version (same inputs → same outputs). That enables deeper mods such as widescreen and real HD rendering. It isn't required for v1.

## Build from your copy

1. `scripts/bootstrap` (`scripts/bootstrap.ps1` on Windows) finds Python 3.10+ and runs `tools/mtport/bootstrap.py`, which verifies `original/*.ipa` against `original/SHA256SUMS`, extracts it to `work/ipa/` with `zipfile` (checking every entry name first, no `unzip` needed), splits the slices into `work/slices/` with a portable fat Mach-O splitter (`tools/mtport/fat.py`, no `lipo`) and writes `work/bootstrap.json`, which later tools read for paths and hashes.
2. The asset pipeline, `scripts/pipeline [run|check]` (`scripts/pipeline.ps1` on Windows; the work is `tools/mtport/pipeline.py`), converts the bundle into `assets-out/`: CgBI PNGs become standard PNGs, maps, sprite projects, tables, strings and the nib become JSON, scripts become `.dis` listings, the `png/**/*.dat` packs become single images, and standard files are copied. Every bundle file gets one outcome (converted, copied or ignored with a reason) in `assets-out/manifest.json`, with content hashes; runs are incremental (a second run writes nothing) and outputs are invalidated by a hash of the parser code ([ADR 0011](adr/0011-asset-pipeline-manifest-and-incremental-runs.md)). The runtime can also read the original files directly. The viewers render from the same parsers into `assets-out/viewers/` ([ADR 0010](adr/0010-asset-pipeline-and-viewers.md)). Their page scaffolding (escaping, page shell, sortable tables, owned output directory) is `tools/mtport/htmlpage.py`; the data-table browser is `python3 -m mtport.tablebrowser build|check` (`assets-out/viewers/tables/`); the map viewer is `python3 -m mtport.mapview build|check|export|batch` (`assets-out/viewers/maps/`); the sprite/animation viewer is `python3 -m mtport.spriteview build|strip|batch` (`assets-out/viewers/sprites/`).
3. The recompiler, `python -m recomp all` (standard library only, [ADR 0014](adr/0014-recompiler-design.md)), writes the generated C to `work/gen/` and its reports to `work/recomp/`.
4. CMake (≥ 3.28) fetches the pinned dependencies into `build/_downloads/` (hash-checked, cached; [ADR 0003](adr/0003-dependencies.md)) and builds `runtime/` + `platform/` + `work/gen/` into `build/<preset>/`. One command per OS, e.g. `cmake --workflow --preset mac-debug`, configures, builds and tests ([ADR 0004](adr/0004-build-presets-and-generators.md)); the `<os>-release` workflows also package the kit with CPack ([ADR 0023](adr/0023-local-ci-and-packaging.md)), the own-code port kit a GitHub Release carries; the `mac-app` workflow builds the self-contained, ad-hoc signed game app from the user's IPA, for their machine only ([ADR 0064](adr/0064-macos-game-app.md)); `scripts/release` builds the release's kits locally from a tag and guards them against generated or derived content ([ADR 0024](adr/0024-release-contents-and-flow.md)). The top-level `CMakeLists.txt` has the targets `runtime` (static library), `MapleThief` (the executable; a `.app` bundle on macOS), `tools` / `recomp` (byte-compile the Python packages), and `maplethief_gen`, the static library of the generated C. `cmake/GeneratedCode.cmake` adds that target only when `MAPLETHIEF_GEN_DIR` (default `work/gen`) holds a `gen.cmake`, so a checkout without the IPA configures and builds without it ([ADR 0021](adr/0021-generated-code-partition-and-build.md)).

**CI never sees the IPA.** It builds tools, recompiler and runtime and runs unit tests on synthetic fixtures. Real-asset builds and golden-image tests run locally. Every CI job runs locally first ([ADR 0023](adr/0023-local-ci-and-packaging.md)): `scripts/local-ci` on the Mac runs the linters, the Python tests on 3.10, `scripts/test` on macOS and the Linux job in a pinned Ubuntu 26.04 x86_64 container on a clean checkout, and `scripts\test.ps1` runs on Windows. GitHub Actions (`.github/workflows/ci.yml`, [ADR 0006](adr/0006-continuous-integration.md)) is the confirmation: it runs `scripts/test` on macOS, Windows (MSVC) and Linux for every pull request and manual run, adds the Release presets (including the macOS universal binary and the packaged kits) on manual runs, and runs `scripts/lint` and the Python tests on the minimum and latest Python. Checkout skips Git LFS, and a guard step fails any job in which an `*.ipa` is real content instead of an LFS pointer.

## Testing

Settled in [ADR 0005](adr/0005-test-harness.md). `scripts/test` (`scripts/test.ps1` on Windows) runs everything and fails if anything fails:

- **C/C++**: doctest executables, one per area (`runtime_test`, `golden_test`, …), each test case registered with CTest as `<area>.<test case>`, next to the `platform.smoke` test. They run through `cmake --workflow --preset <os>-debug`.
- **Python**: pytest 9.1.1 from the `test` dependency group, run with `uv run --locked` in `build/python-env/<os>-<cpu>`. Tests marked `real_assets` need `work/ipa/` and are reported as skipped without it (always in CI).
- **Golden images**: the C++ library `maplethief_golden` (`tests/golden/golden.h`) checks a rendered RGBA image against a golden PNG with a per-channel tolerance and a maximum ratio of differing pixels. On failure it writes `<name>.actual.png` and `<name>.diff.png` to `build/test-output/<preset>/`. Synthetic goldens are committed in `tests/golden/data/`. Goldens of real game frames live in `work/golden/` and are never committed. `MAPLETHIEF_UPDATE_GOLDEN=1` (re)writes goldens from the current output. Whole game screens are compared with device screenshots by `platform.device_golden` ([ADR 0044](adr/0044-virtual-clock-and-device-golden-screens.md), `tests/golden/README.md`): the game is driven headless with `--fixed-step` through the runs of `tests/golden/device_screens.json`, and each screen is checked against our own recorded render (`work/golden/ours/`, exact; renderer regressions) and the device screenshot (`work/golden/device/`, with masks for text and animations and a tolerance per screenshot scale). `python3 -m mtport.goldencmp` compares one pair by hand.
- **Recompiler snippets** ([ADR 0015](adr/0015-recompiler-snippet-suite.md)): every `tests/recomp/snippets/**/*.snippet` file is one pytest test that lifts the snippet, compiles it with the host C compiler (MSVC on Windows) and compares the final CPU state and memory with the file. The format and how to add a snippet are in `tests/recomp/README.md`.
- **Differential test** ([ADR 0017](adr/0017-unicorn-differential-testing.md), local only): `scripts/difftest` (`python -m recomp difftest`, `recomp/difftest/`) selects the binary's leaf functions, runs each on 1,000 seeded random inputs in Unicorn and as recompiled C (production and flags-in/out lifts, one driver executable), and compares the end states and every changed byte. A mismatch is reported with its seed in `work/recomp/difftest.md`. 775 of the 786 leaves pass. The synthetic parts (selection, inputs, the C driver on every compiler) run in CI without Unicorn.
