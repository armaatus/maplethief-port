# 154. Threat model: the files a player can supply

- **Status:** Accepted (delegated by Joris, 2026-11-13)
- **Date:** 2026-11-13
- **Issue:** [#320](https://github.com/armaatus/maplethief-port/issues/320) (epic [#287](https://github.com/armaatus/maplethief-port/issues/287)); the gaps it found are [#324](https://github.com/armaatus/maplethief-port/issues/324) and [#413](https://github.com/armaatus/maplethief-port/issues/413)
- **Builds on:** [ADR 0025](0025-guest-memory-and-address-space.md) (guest memory), [ADR 0074](0074-save-files-atomic-writes-sanitising-and-ios-documents.md) and [ADR 0078](0078-save-export-import-backups-and-checks.md) (saves), [ADR 0081](0081-texture-packs-and-nearest-texture-filter.md), [ADR 0106](0106-audio-packs.md) and [ADR 0108](0108-text-packs.md) (packs), [ADR 0085](0085-borders-around-the-picture.md) (border art), [ADR 0105](0105-save-states-in-process-snapshot-at-safe-points.md) (save states), [ADR 0135](0135-accept-an-ipa-by-its-main-binary.md) (the IPA), [ADR 0137](0137-network-use-and-the-update-notice.md) (the update check), [ADR 0149](0149-pack-manifest-several-packs-and-what-the-project-hosts.md) (the pack manifest)

## Context

The port and its frontend are C++ with hand-written parsers (zip and inflate, NIBArchive, binary plist, JSON, WAV, `.strings`, the save files, the state file, the settings) beside stb_image, dr_mp3 and dr_flac. v0.1.0 is out, and players will load files other people made: packs, save exports, save states. Several ADRs already call one kind of file untrusted and set its limits (0081, 0085, 0105, 0106, 0108, 0137, 0149), each in its own words. No single decision says which files are untrusted, what the port promises when it reads one, and what it does not promise. The fuzzing (#322, #323) and the fixes (#324) need that target.

The original game trusts its files ([docs/re/original-bugs.md](../re/original-bugs.md), bugs 6 and 7). Its save loaders take ids, skill levels and the map from `theif` and `quest` as they are, and its loaders for `.map`, `.att`, `.mapprj` and the sprite bundles have no bounds. The port runs the game's code as recompiled guest code inside guest memory (ADR 0025): every guest access lands in the guest's own address range, a 4 GiB reservation or a checked 512 MiB arena, so a wild guest access hits a guest page or traps (`runtime/src/boot/trap.c`, the crash file of #198). It does not reach host memory. The host side (the HLE runtime and the frontend) is where a hostile file could do harm.

The game is offline. The only network use is the opt-in update check (ADR 0137).

A read of every parser on 2026-11-13 (for this ADR) found them bounded for the most part, with a few gaps; the table below records what holds today, at `4b6456be`.

## Options considered

1. **One threat model for every file kind, with a table of parsers, limits and proving tests** (this ADR). Each later change to a parser updates one row. The fuzzing and the sanitizer job have a list to cover.
2. **Keep the per-ADR rules.** No new document, but the rules differ in wording and in strength (some ADRs promise "a refused file changes nothing", some don't say), and no one place lists the files nobody called untrusted (`gamecenter.json`, saves copied in by hand, the state file's path fields).
3. **Treat the game's saves as trusted, as the original does.** Only a hand-edited or damaged save reaches the unchecked fields, and ADR 0074 chose to leave them alone. But save exports are made to be shared (ADR 0078), and a save in a synced `save_dir` or the iOS Files app reaches the game without the import's checks. Rejected for the fields the game uses as indices: see the decision.

## Decision

Option 1. Decided by the agent (delegated by Joris, 2026-11-13); Joris can veto it in the PR.

### The attacker

**Someone who shares a file**: a pack, a save export, a save state, a settings or bindings file, a border image, or a modified IPA, posted where a player downloads it. They control every byte of the file and its name, and the names inside an archive. They do not control the player's machine, the port's binary, or the player's own copy of the game, and they cannot watch or answer the player.

A **network attacker** between the port and GitHub's API is in scope only for the update check (ADR 0137): TLS stops them, and the response is untrusted data like a file.

### Trust per file kind

| File kind | Who writes it | Trust |

### What the port guarantees

For every untrusted file, whatever its bytes and its name:

1. **No host memory access out of bounds.** No read or write outside a host allocation, no use after free, no undefined behaviour that a sanitizer reports. A fault inside guest memory is not a host fault: it is a guest trap with a crash file, never a host exploit.
2. **No host path outside the data and game folders.** Nothing a file contains makes the port open, create, rename or delete a host path outside `<data dir>` and the imported `game/`. A file's name or a path inside it is never joined to a host directory without a check that refuses absolute paths, `.` and `..` components, backslashes, drive letters and NUL, on every system. Symlinks inside a pack or a save export are not followed.
3. **Bounded memory and time.** A file's size is checked before it is read. Every allocation a parser makes is bounded by a constant (per entry and in total), or by the input's size times a constant, before it is made. Every parser's work is linear in what it allocates, or bounded by such a constant. An allocation that still fails is a refusal, never a termination.
4. **A refused file changes nothing.** A refusal is logged with its reason. The game's state, the player's other files and the data folder are as they were. The game uses its own asset where a pack's file was refused. The one exception is a save the game would read with a failing check: it is moved aside (below), so the game cannot overwrite it.

The guarantees hold for the **host**. A file that is accepted can still change the game within its rules: a pack can draw, play or say anything; a save can hold any character the checks allow.

### Decisions on the gaps the survey found

The read of 2026-11-13 found gaps outside #324's list. Each is decided here and built in #413, after #324:

- **(a) Saves copied in by hand.** The guest's loaders trust every field, so the guarantee needs a check before the guest reads one. The file layer runs ADR 0078's full `mt_saves_check` when the guest opens `theif<N>` or `quest<N>` directly in `saves/`, beside `mt_saves_sanitise`. A file that fails is moved to `backups/refused/<time>/` with its reason, logged and shown once, and the guest sees no file. Moved, not hidden, because the game writes a new save over a missing slot. A valid file still passes unchanged (ADR 0074). Bugs 6 and 7 stay kept for the game's own writes, which always pass.
- **(b) Symlinks.** The pack loaders and the save import's folder source skip a symlink (`symlink_status`), logged once. A link a player made in their own data folder is their choice (out of scope).
- **(c) Allocation failures.** `bad_alloc` from parsing an untrusted file is caught at the parser's entry and becomes a refusal; none escapes a `noexcept` function (`mt_snapshot_restore`, `mt_snapshot_read_header`).
- **(d) `gamecenter.json`.** At most 1 MiB and 4,096 elements; `\u0000` is refused. The lone surrogate is #323's.
- **(e) Audio pack effects.** The rate and the channels come from the header before an effect is decoded, as ADR 0106 says.
- **(f) The Apple update fetcher.** The 4 MiB cap is applied while the body streams, and redirects go to HTTPS only. Linux's redirects are #324's.
- **(g) `bootstrap.py`.** `extract_ipa` gets the C++ import's caps: 64 MiB an entry, 1 GiB in total, 4,096 entries.
- **(h) Pack size.** A texture or audio pack indexes at most 65,536 files; the rest are skipped and logged.

### Out of scope

- **Someone with access to the player's machine** or their data folder beyond handing them a file: they can replace the port itself. A symlink or a file the player puts in their own data folder is their choice.
- **The game's behaviour inside guest memory.** A save or a state can crash the game (a trap, ADR 0151's recovery point, #198's crash file); that is a lost session, not a breach. Bugs 6 and 7 stay kept for files the import verified. Beyond the restore's own paths, the HLE's checks against a guest program made hostile by a crafted state are best effort: #322 and #323 fuzz the readers, not every HLE call.
- **The trusted game data.** The player import accepts only the known IPA, so the game's own loaders never see a crafted `.map`. A developer who builds from a modified copy (ADR 0135 accepts other data files with the right binary) runs what they built.
- **Denial of service within the limits.** A file at its caps may be slow (a 128 MiB MP3's frame walk, a 768 MiB section); the caps bound it, nothing more.
- **Who made a file.** Packs, saves and states are not signed, and the binary's hash in a state is no signature (ADR 0148 keeps the downloads themselves unsigned).
- **Sandboxing the process** (epic #287's own scope).

## Consequences

- Every parser of an untrusted file has one row here. A change to a parser's limits updates its row in the same PR, and a new kind of file gets a row before it ships (ADR 0149's manifest with #370).
