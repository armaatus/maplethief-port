# 36. CoreGraphics and UIKit drawing: our own software rasterizer, CG objects as CF types, one bundled font (NanumGothic) for every face

- **Status:** Accepted
- **Date:** 2026-10-28
- **Issue:** #51
- **Builds on:** [ADR 0003](0003-dependencies.md) (stb, pinned downloads), [ADR 0029](0029-objective-c-runtime-services.md) (host classes, `maplethief/objc/host.h`), [ADR 0032](0032-corefoundation-object-model.md) (CF objects are guest objects with host state)

## Context

The game draws with CoreGraphics and UIKit only to make bitmaps: text textures, decoded PNGs, map tiles, and Chartboost's buttons. Everything on screen then goes through OpenGL ES ([ANALYSIS.md → Rendering](../ANALYSIS.md#rendering)). #51 has to implement the 40 CoreGraphics imports (37 functions, 3 data constants) and UIKit's 9 drawing functions, and the classes the game sends drawing messages to: `UIImage`, `UIFont`, `UIColor`, `UIBezierPath`, and `NSString`'s UIKit drawing selectors.

What the game does with them (decompiled 2026-10-28, armv7 slice; senders in [re/imports.md](../re/imports.md)):

- **Text textures.** `TextCache_DrawText` (`0x9031`) converts its C string with `stringWithCString:encoding:` (EUC-KR, with fallbacks), then makes a 512 × 32 bitmap context (32 × 32 for one character) over a global buffer: `CGBitmapContextCreate(buf, w, 32, 8, w * 4, rgb, kCGImageAlphaPremultipliedLast)`. It clears the buffer, sets `CGContextSetGrayFillColor(1, 1)` and `CGContextSetTextDrawingMode(kCGTextFill)`, pushes the context with `UIGraphicsPushContext`, gets `[UIFont fontWithName:@"MarkerFelt-Thin" size:]` (the CFString literal at `0x117E74`) and `-fontWithSize:`, sends `-drawAtPoint:(0, 0) withFont:` and keeps the returned width. Then it pops, releases the context and uploads the buffer through `0x7AD9`. The context's CTM is **not flipped**, so the text lands upside down at the bottom of the bitmap. The device drew it that way, and the GL side draws the texture to match. Measurement (`0x72F1`) uses `-sizeWithFont:` with the same font, and only the width.
- **PNG textures.** The texture loader `FUN_00009534` sends `[[UIImage alloc] initWithData:]` and reads `CGImageGetWidth/Height/BitsPerComponent/BytesPerRow/AlphaInfo`. Alpha info 1–4 becomes `kCGImageAlphaPremultipliedLast`, anything else `kCGImageAlphaNoneSkipLast`, each `| kCGBitmapByteOrder32Big`. It makes a power-of-two context, flips it (`TranslateCTM(0, potH)`, `ScaleCTM(1, -1)`), draws the image at `(0, potH − h, w, h)` and calls `glTexImage2D` on the buffer.
- **Map tiles.** `FUN_0000d6d0` takes the decoded tile sheet's bytes with `CGDataProviderCopyData` and copies 16 × 16 tiles out. It assumes 4 bytes per pixel, RGBA, alpha in byte 3, and skips alpha 0. Then `CGImageCreate` with the sheet's parameters, `-initWithCGImage:` and `UIImagePNGRepresentation`.
- **Scaled portraits.** `FUN_0001e96c` scales by 1.5 through `-[EAGLView imageWithImage:scaledToSize:]` (`0x3251`): `UIGraphicsBeginImageContext`, `-drawInRect:`, `UIGraphicsGetImageFromCurrentImageContext`, `UIGraphicsEndImageContext`.
- **One pixel of an image.** `colorAtPixel:onImage:` (`0xB4DB5`) makes a 1 × 1 context over 4 stack bytes, with the image's bits per component and **bytes per row**, sets `kCGBlendModeCopy`, translates by (−x, −y) and draws the whole image. A context must never write past `width × 4` bytes of a row.
- **The shell** uses `+[UIImage imageNamed:]` (80 sites), `UIColor` (backgrounds) and `UIFont` (`MarkerFelt-Thin`, `Helvetica`, `Helvetica-Bold`) for its views, which are #54's.
- **Chartboost only:** `UIBezierPath`, `CGGradientCreateWithColors` with both gradient kinds, `CGContextAddPath` + `CGContextClip`, `UIGraphicsBeginImageContextWithOptions`, `UIGraphicsGetCurrentContext`, `+boldSystemFontOfSize:`, `+imageWithData:`, `-set`, `-scale`, `-stroke`, `-setLineWidth:`. Chartboost never runs ([ADR 0026](0026-objective-c-strategy.md)), but these are implemented anyway, so that no import is left to the unimplemented-import handler.
- **Fonts.** The binary names `MarkerFelt-Thin`, `Helvetica` and `Helvetica-Bold`. Korean text was drawn by the iOS font fallback (AppleGothic). `ScriptExtra.strings` gives `SkyCanvas` a font name, `Gulim` / `굴림`, which no iOS 4 device had. None of these fonts may be shipped.

## Options considered

**Rasterizer.**

1. **Our own small rasterizer.** It covers what the game draws: axis-aligned and rounded rectangles, strokes, two gradient kinds, a clip mask, image draws, glyph coverage, and Normal, Copy and Clear compositing on 8-bit premultiplied RGBA. Each part is a few hundred lines. It is deterministic on every compiler and has no dependency.
2. **A 2D library** (Blend2D, plutovg, cairo, Skia). These are complete, but much bigger than the need, and cairo and Skia pull in large build trees. Their output can change between versions. None of them gives CG's exact semantics for free (the CTM's y-up device space, UIKit's flip, `CGContextDrawImage`'s orientation), so the glue code remains anyway.
3. **The GPU.** These bitmaps feed `glTexImage2D` or are read back on the CPU (`CGDataProviderCopyData`, `colorAtPixel:`). A GPU path would need a readback for every one of them.

**Font.** Any replacement must cover Latin and Hangul, be redistributable, and be close enough to Marker Felt and Helvetica's metrics that the game's centred and fitted text still fits.

1. **NanumGothic Regular** (NHN, SIL OFL 1.1): 2 MB TrueType, Latin, all 11,172 modern Hangul syllables, Hangul jamo, and the KS X 1001 punctuation and arrows the game uses. Its Latin is a plain grotesque, close to Helvetica's widths.
2. **Noto Sans KR / Noto Sans CJK** (OFL): complete, but 5–16 MB per weight, CFF outlines (slower to rasterize in stb_truetype), and Hanja the game never shows.
3. **A Marker Felt look-alike for Latin plus a Hangul font.** Closer to the device's look, but that is two fonts to fall back between, and a decision about game feel that needs device screenshots first.

**Glyph rasterizer.** stb_truetype (public domain / MIT, one header at the stb commit we already pin) or FreeType (FTL or GPL-2, a CMake build, more than we need).

## Decision

- **Our own rasterizer (option 1)** in `runtime/src/cg/` (`cg_objects.h` describes the module):
  - **Pixels.** Contexts draw 8-bit premultiplied RGBA into memory of any 32-bit CG layout: component order, byte order and skip byte come from `CGBitmapInfo`. `CGBitmapContextCreate` accepts premultiplied-alpha or no-alpha 32-bit formats, as CG does, and refuses the rest with CG's "unsupported parameter combination" log. A context over guest memory draws straight into it and never touches row padding.
  - **Coordinates.** User space goes through the CTM to Quartz device space (y up), and device row 0 is the top row of memory. UIKit's drawing calls (`-drawAtPoint:withFont:`, `-drawInRect:`, `UIBezierPath`) draw as if user space were y down, which is true only on a context that `UIGraphicsBeginImageContext` flipped. On the game's unflipped TextCache context, text comes out upside down at the bottom of the bitmap, as on the device. `CGContextDrawImage` puts the image's top row at the rect's maximum y, and `-drawInRect:` at its minimum y.
  - **Coverage.** Anti-aliased polygon coverage uses exact signed-area accumulation (the font-rs / stb_truetype v2 method) and the nonzero rule. Curves (rounded rectangles) are flattened. Strokes are quads with butt caps and no joins, which is enough for Chartboost's single stroke. The clip is a per-pixel coverage mask (`CGContextAddPath`, then `CGContextClip`), saved and restored with the graphics state.
  - **Compositing.** Normal (source over), Copy and Clear. Other blend modes draw as Normal and are logged once; the game sets only Copy.
  - **Images.** Bilinear sampling. A whole-pixel 1:1 placement is copied instead, so that the texture loader's draw and `colorAtPixel:` read the decoded pixels exactly.
  - **Gradients.** Linear and radial (CG's two-circle form), with stop interpolation in straight RGBA and the before-start and after-end extension options.
- **CG objects are CF types** ([ADR 0032](0032-corefoundation-object-model.md)): each `CGContext`, `CGImage`, `CGColor`, `CGColorSpace`, `CGDataProvider`, `CGGradient` and `CGPath` is a guest `__NSCFType` instance whose content is host state. So `CFRetain`, `CFRelease` and the `CGxxxRelease` functions work on all of them, and `CGxxxRelease(NULL)` is allowed. A `CGImage` reads its pixels from its data provider: a `CFData` in guest memory, or host bytes for decoded PNGs and snapshots. `CGColorGetComponents` returns a guest array the colour owns.
- **PNG.** `UIImage` decodes with stb_image (`runtime/src/cg/codec.cpp`, Apple CgBI included, [ADR 0003](0003-dependencies.md)) into straight RGBA. That is `kCGImageAlphaLast` when the file has alpha (an alpha channel or `tRNS`), else RGBX `kCGImageAlphaNoneSkipLast`: 8 bits per component, 32 per pixel, rows of `4 × width` bytes. This is what the texture loader and the tile cutter read from ImageIO on iOS 4. `UIImagePNGRepresentation` writes RGB or RGBA with stb_image_write.
- **UIKit's drawing classes** are host classes: `UIImage` (`+imageNamed:` with a per-process cache, `+imageWithContentsOfFile:`, `+imageWithData:`, `-initWithData:`, `-initWithCGImage:`, `-CGImage`, `-size`, `-scale`, `-drawInRect:`), `UIColor` (the constructors the game and Chartboost use, `-CGColor`, `-set`, `-setFill`, `-setStroke`), `UIBezierPath` (Chartboost's selectors) and `UIFont`. `+imageNamed:` looks up `<name>.png` in the bundle when the name has no extension, or when the name with its extension is not found (`v1.0.8`). The UIGraphics context stack retains what it holds. An image context is premultiplied RGBA, or RGBX when opaque, in host memory, with the screen scale 1 for `scale` 0.
- **NSString's drawing selectors** (`-drawAtPoint:withFont:`, `-sizeWithFont:`) are a **host category** on #49's `NSString`. `mt_objc_host_category` and `mt_objc_add_host_category` are added to `maplethief/objc/objc.h`, with a category registry in `runtime/src/objc/classes.cpp`, so one issue can add methods to another issue's class without editing its files.
- **One bundled font: NanumGothic Regular (font option 1)** stands in for every face. `+[UIFont fontWithName:size:]` knows `MarkerFelt-Thin`, `MarkerFelt-Wide`, `Helvetica`, `Helvetica-Bold`, `Helvetica-Oblique`, `Helvetica-BoldOblique`, `HelveticaNeue`, `HelveticaNeue-Bold`, `AppleGothic`, `ArialMT` and `Arial-BoldMT`. It returns nil (logged once) for any other name, as UIKit did for a font the device lacked, `Gulim` included. Bold faces and `+boldSystemFontOfSize:` are synthesized: the glyph coverage is widened by `max(1, round(size / 14))` device pixels. Oblique faces are drawn upright.
  - **The file** is downloaded at configure time from google/fonts at a pinned commit, with its SHA-256 (`cmake/Dependencies.cmake`, `maplethief_use_font`), and embedded into the runtime as a generated source in the build tree. Nothing of it is committed. Its `OFL.txt` is installed as `licenses/NanumGothic-OFL.txt` in the kit. The OFL allows bundling with software; the font is not sold on its own and keeps its name.
  - **Metrics.** Sizes are the font's em size in points (`stbtt_ScaleForMappingEmToPixels`). The line height is the font's ascent − descent + line gap, and the baseline sits at `y + ascent`. Widths are the kerned advances. `-sizeWithFont:` rounds both up to whole points, as UIKit did. A single-line draw skips control characters (`\r`, `\n`).
  - **Glyphs** are rasterized by **stb_truetype 1.26**, from the same stb commit as stb_image. On an axis-aligned CTM, a glyph is rendered at its subpixel x offset and placed on whole device pixels with the baseline rounded, so it is copied, not resampled. Otherwise it is sampled bilinearly. Glyphs are drawn in the fill colour through the clip and blend mode. `kCGTextInvisible` measures without drawing, and the stroke modes fill (logged once).
- **Unsupported uses are logged, never silent.** Each of these is logged and ignored: an invalid context, gradient or image argument; an unsupported format or blend mode; a decode array in `CGImageCreate`; a drawing call with no current context; an unbalanced pop.

## Consequences

- **Tests.**
  - In CI: `tests/cpp/cg_test.cpp` (in `objc_test`) calls every import through its HLE entry, with the iOS argument layout. It runs the game's own sequences: TextCache, the texture loader with an exact check of the copied pixels, the tile cutter, `colorAtPixel:` with guard bytes, and the scaled copy. It also covers the CgBI decode of a synthetic CgBI file, PNG round trips, `UIFont` names and metrics, font coverage (ASCII, all 2,350 KS X 1001 Hangul syllables and the jamo), and the UIGraphics stack.
  - **Golden images** of synthetic drawings live in `tests/golden/data/cg_*.png`: linear and radial gradients, a rounded-rect clip with a gradient and strokes, Latin and Hangul text with synthetic bold, the upside-down TextCache bitmap, the flipped texture upload, and the 1.5× scaled copy. They are compared with a tolerance of 2 per channel on 0.2 % of the pixels, because floating-point contraction differs between compilers.
  - Locally (real assets): `cg_real_test` decodes every PNG of the bundle (1,322 files, 113 CgBI) through `+imageWithContentsOfFile:`, checking the size and alpha info. It decodes the 115 root PNGs through `+imageNamed:` and the 473 PNGs of the `png/**/*.dat` packs through `-initWithData:`. `tests/test_hle_cg_real.py` checks that every CG and UIKit C import of the slice has a registry entry. It also checks that the pinned font has a glyph for every character of the game's `.strings` files and data-table strings.
- **The runtime grows by about 2 MB** (the embedded font). The kit ships the OFL text.
- **The text looks different from the device.** NanumGothic is not Marker Felt: the Latin is a plainer sans-serif, and Hangul is NanumGothic's instead of AppleGothic's. Widths differ by a few percent, so text centred with `-sizeWithFont:` stays centred, but where a line wraps or clips can move a little. Judging this against device screenshots needs Joris (needs-human).
- **What the font lacks.** It has no kana, Cyrillic, Greek, Roman-numeral, circled-Hangul or unit-symbol glyphs (557 KS X 1001 characters). None of them occurs in the game's text. They would draw as the font's missing-glyph box.
- **Other issues build on this.** #54's `UILabel`, `UIButton` and `UIImageView` draw through `draw_text`, `text_size`, `font_of`, `uiimage_cgimage` and the context functions of `cg_objects.h`. #117's first GL frame uploads the bitmaps these contexts fill.
- **How we'd know this was wrong:**
  - **Text overflows or is cut off** where the device's fit. Then the metrics need calibrating against device screenshots, or a closer Latin font.
  - **A texture has the wrong orientation.** That would show the CTM or `CGContextDrawImage` convention is wrong. The golden test of the texture upload pins the convention we believe.
  - **A drawing path the game uses logs an unsupported mode.** Then that mode needs implementing.
