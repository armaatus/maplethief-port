# 45. Audio: a deterministic mixer in the runtime, pulled by one SDL3 audio stream

- **Status:** Accepted
- **Date:** 2026-10-29
- **Issue:** #61
- **Builds on:** [ADR 0003](0003-dependencies.md) (our own OpenAL layer, SDL3, dr_mp3), [ADR 0033](0033-gcd-worker-threads-and-main-queue.md) (one guest thread), [ADR 0038](0038-gl-recording-eagl-silent-audio-boot-to-first-frame.md) (silent audio: handles, names, error rules), [ADR 0039](0039-rendering-backend-software-rasterizer.md) (the same split for graphics: deterministic core in `runtime/`, SDL only in `platform/`), [ADR 0044](0044-virtual-clock-and-device-golden-screens.md) (the virtual clock)

## Context

The game's sound is small and simple ([re/audio.md](../re/audio.md)):

- **Effects:** 26 WAVs, 16-bit PCM, mono 8 kHz (13), mono 22.05 kHz (11), stereo 44.1 kHz (2). All are decoded at start-up into one OpenAL buffer and one source per id. A source is only ever played (`alSourcePlay`): never looped, stopped, positioned or given a gain. Replaying a playing source restarts it. The only other AL state is the listener gain (0 or 1: the effects switch).
- **Music:** 18 MP3s (44.1 kHz and 22.05 kHz stereo), one `AVAudioPlayer` per track, looping for ever at volume 0.7 or 0. In practice one track plays at a time. `-stop` keeps the position, `setCurrentTime:0` rewinds.
- **No 3D audio, no streaming AL buffers, no queueing.** The game asks `alcGetProcAddress` only for `alBufferDataStatic`, in a branch that can't run.

ADR 0003 decided on our own OpenAL layer "onto SDL3 audio streams". ADR 0038 then built the silent version in `runtime/src/audio/`, and `runtime/` does not link SDL3 (graphics made the same choice in ADR 0039: the core is deterministic and SDL-free, the platform presents). What is open is where mixing and resampling happen and what crosses the runtime/platform line.

M6's exit criteria: all 44 sounds play when triggered, the music loops and switches per map, no dropouts over 30 minutes.

## Options considered

1. **One SDL_AudioStream per AL source and per player**, all bound to one device. SDL mixes and resamples.
   - Pro: least code of ours.
   - Con: `runtime/` would link SDL3, and every test would need an audio device (or SDL's dummy driver) to hear anything. The mix is SDL's, so output is not byte-stable across SDL versions, and can't be checked in a test except by ear.
   - Con: "restart a playing source" becomes clear-and-refill a stream from the guest thread while the device thread reads it.
2. **Our own mixer in `runtime/`, pulled by one SDL3 audio stream in `platform/`.** The runtime renders a fixed output format on request; the platform opens one device stream whose callback calls it.
   - Pro: deterministic. The same calls give the same samples on every OS and in the Linux container, so tests compare mixed output exactly (synthetic tones, a capture of a scripted boot). The mixer is about 300 lines: 44 one-shot voices and one or two music streams.
   - Pro: the runtime stays SDL-free, as for graphics.
   - Con: we write the resampler (linear interpolation is enough for 8 kHz effects and is what Apple's OpenAL did at its default quality).
3. **OpenAL Soft.** Rejected in ADR 0003 (size, LGPL, still needs every thunk).

## Decision

- **Option 2.** The mixer lives in `runtime/src/audio/mixer.{h,cpp}` (internal) behind a pull API in `maplethief/audio.h`. `platform/` owns the device.
- **Output format:** 44,100 Hz, stereo, interleaved `float` in [−1, 1] (`MT_AUDIO_RATE`, `MT_AUDIO_CHANNELS`). It is the rate of most of the content (the 22.05 kHz files are an exact 2×). SDL's stream converts to the device's own rate and format.
- **Pull API** (C, callable from any host thread):
  - `void mt_audio_render(float *out, uint32_t frames)`: mixes the next `frames` frames into `out` (overwrites it), in blocks of at most 4,096 frames per lock. Always produces output, silence when nothing plays; never blocks on the guest.
  - `mt_audio_set_gain(mt_audio_bus bus, float gain)` / `mt_audio_get_gain` for the buses `MT_AUDIO_BUS_MASTER`, `MT_AUDIO_BUS_MUSIC`, `MT_AUDIO_BUS_EFFECTS` (user settings, #64; clamped to [0, 1], NaN ignored, all 1 at start), and `mt_audio_set_muted(bool)` / `mt_audio_get_muted` (unfocused window). These multiply the game's own gains; they never change what the game reads back, and they survive a new process.
  - `mt_audio_get_output_stats()` (named like `mt_audio_get_stats`; the type is `mt_audio_output_stats`): frames rendered, render calls, the longest render in microseconds, the late callbacks the platform reported (`mt_audio_note_late`), and the effect and music voices playing now, for the soak test. `mt_audio_reset_output_stats()` starts them again.
  - `mt_audio_test_tone(hz, ms)`: a 16-bit mono 22,050 Hz sine at half amplitude as an effect voice outside any OpenAL state, for the manual device check.
- **Voices.**
  - **Effects:** an AL source with a filled buffer is a voice, keyed by its source name. `alSourcePlay` (re)starts it at frame 0. Each voice keeps a 32.32 fixed-point read position and step (`floor(buffer_rate × 2³² / 44,100)`: 2³¹ for 22,050 Hz, 779,132,389 for 8,000 Hz) and interpolates linearly between 16-bit samples **in integers**: `s0 + ((s1 − s0) × frac) >> 32`, with silence past the last frame (so a voice ends with one fade step to zero). The result times `listener_gain × effects_bus / 32,768` is added in float. Mono goes to both channels at unit gain. The step is rounded down, so an 8 kHz effect of 400 frames plays 2,206 output frames, not 2,205.
  - **`alBufferData` copies** the guest's bytes into an immutable host `Pcm` shared by the buffer and its voices (the game frees its buffer right after; a voice still playing old samples keeps them when the buffer is refilled). `AL_FORMAT_MONO8`/`STEREO8` are unsigned (128 is silence, scaled × 256), `MONO16`/`STEREO16` signed little-endian. A size that is not a whole number of frames is `AL_INVALID_VALUE`, more than 64 MiB `AL_OUT_OF_MEMORY` (the game's largest is about 271 KB); a null `data` is that many bytes of silence (as OpenAL Soft). A bad guest range faults the guest, as the device's copy would.
  - **`alcGetProcAddress` returns NULL for every name.** The game asks for exactly one, `alBufferDataStatic` (one call site of the import: Apple's `alBufferDataStaticProc` `0x1D5F5`, the string at `0xE3764`; [re/imports.md](../re/imports.md), [re/libraries.md](../re/libraries.md)). That function checks the pointer for NULL before calling it, and it is reached only from `SoundPlayer_LoadEffects`'s `id == 0` branch, which cannot run (0 is a music id). Providing it would need a guest-callable address for a host function outside the import table, which the dispatcher (ADR 0014) does not have, and a buffer that the audio thread reads in guest memory while the guest thread may write it. NULL is what a device without the extension answers, and the game handles it.
  - **Music** (#63): an `AVAudioPlayer` that plays is a music voice, keyed by the player, that pulls 16-bit PCM from a `mix::MusicStream` (`rate()`, `channels()` 1 or 2, `read(out, frames)`: fewer frames than asked means the stream ended; a looping stream loops inside `read`) in blocks of at most `mix::kMusicBlock` = 4,096 frames, inside `mt_audio_render`, under the lock (dr_mp3 streamed, not decoded whole: the game never frees a player). It is resampled exactly like an effect and mixed at `player_volume × music_bus`. `mix::music_play(key, stream, volume)` starts or resumes it, `music_stop` stops it **keeping the frames it has pulled**, so the next `music_play` goes on from the exact frame (`-stop` keeps the position), `music_set_volume`, `music_remove` (a released player), and `music_edit(key, fn)` runs `fn` on the stream under the lock after dropping what the voice had buffered (`setCurrentTime:`). The mixer side is built and tested with a synthetic stream in #61; #63 writes the dr_mp3 stream and calls these from `avfoundation.cpp`.
  - **The mix:** effects in source-name order, then music in key order, summed in float, times the master bus (0 when muted), clamped to [−1, 1]. `mixer.cpp` is compiled without floating-point contraction (`maplethief_strict_fp`), so every operation rounds as written and a mix is the same bytes on every host.
- **Threads and the lock.** The guest thread changes voices (inside HLE calls), the device thread renders. One mutex guards the whole mixer; it is held only for short host-side work (start a voice, swap a `Pcm` pointer, render a block of at most 4,096 frames), never across guest code and never while reading guest memory (the copy is made before the lock). Old `Pcm`s and streams are released outside it. The guest never waits on the audio thread. Music decoding happens under the same lock; if that proves too slow for the callback, decoding moves to a ring buffer filled outside the lock (the soak test shows which).
- **The platform** (`platform/src/audio_out.{h,cpp}`, `AudioDevice`): `SDL_InitSubSystem(SDL_INIT_AUDIO)`, `SDL_OpenAudioDeviceStream(SDL_AUDIO_DEVICE_DEFAULT_PLAYBACK, {SDL_AUDIO_F32, 2, 44100}, callback)`, opened paused and resumed at the game's first run-loop turn. The callback renders exactly the frames SDL asks for and reports a late callback (`LateDetector`) when the time since the previous one exceeds 1.5 × the duration of the audio it delivered; calls less than 1 ms apart count as one delivery (SDL's converter can ask twice in a row). No audio device (none present, an unknown `SDL_AUDIO_DRIVER`, `--no-audio`) is not an error: the game runs and is silent. The fixed-step mode opens no device (its time is virtual: playing it in real time would mean nothing). `SDL_AUDIO_DRIVER=dummy` is a device that pulls in real time without sound (CTest uses it).
- **Deterministic capture** (`AudioCapture`): `MapleThief --audio-capture FILE.wav` writes the mixed output as a 16-bit stereo 44,100 Hz WAV **instead of** playing it (the mixer has one reader). Samples are `lround(clamp(x) × 32,767)`. After each run-loop turn the platform renders the frames up to the run's time: `floor(t × 44,100 / 10⁹)` frames in all, so each step's remainder is carried (735 or 736 per 16.667 ms). Under the virtual clock (`--fixed-step MS`, ADR 0044) `t` is the clock's time after the step's advance, which also covers any GCD sleep since the last turn; a call the guest makes at virtual time `t` starts at frame `floor(t × 44,100 / 10⁹)`, and a scripted run gives the same file every time and on every OS. Without `--fixed-step` `t` is real time since the start. Tests read captures; they never need a device.
- **The silent state rules stay** (ADR 0038): handles, names, `alGetError`'s first-error rule, `AL_INVALID_OPERATION` without a current context, and the game's own `alSourcePlay(-1)` from `ResumeBGM` before any music (`AL_INVALID_NAME`). New, as OpenAL specifies: `alSourcei(AL_BUFFER)` on a playing source and `alDeleteBuffers` of a buffer attached to a source are `AL_INVALID_OPERATION`; `alDeleteSources` stops the source; a source without samples (the game's music ids) stops at once on `alSourcePlay`. Other `alSourcei` parameters and other listener parameters are accepted and have no effect (the game sets none). The effects are mixed only while a context is current and not suspended: `alcMakeContextCurrent(NULL)` or `alcSuspendContext` pause them (positions kept), `alcMakeContextCurrent(context)` plus `alcProcessContext` resume them, which is what the game's interruption listener does. Destroying the last context stops every effect voice. A new process (a new current ObjC runtime) stops every voice; the buses, mute and output stats stay.

## Evidence

- **CI (synthetic):** `tests/cpp/audio_test.cpp` (in `objc_test`, strict FP): a generated tone through `alBufferData` → `alSourcePlay` → `mt_audio_render` compared sample for sample at 44.1 kHz (the guest's copy overwritten after the call), at 22,050 Hz (every other frame halfway) and 8,000 Hz (the 32.32 rule written out again in the test), stereo, `MONO8`/`STEREO8`; restart, two sources summed, the clamp, sources without samples, the new error rules; the listener gain, the three buses, mute, clamping of gains; suspend/process and `alcMakeContextCurrent(NULL)` keeping the position; the game's start-up sequence with no AL error and its `alSourcePlay(-1)`; `alcGetProcAddress`; a render thread beside 400 rounds of guest calls; a new process; the music voices with a synthetic `MusicStream` (blocks ≤ 4,096, the exact frame after stop/play, volume × bus, `music_edit` rewinding, an ending stream). `tests/cpp/audio_out_test.cpp` (in `platform_test`): the frames a span covers, the late rule, two scripted captures byte-identical with the right header and samples, the device stream on the dummy driver and an unknown driver (silent, no error). CTest `platform.audio_tone`: `MapleThief --audio-test-tone` on the dummy driver pulls at least the tone's 66,150 frames.
- **Local (real assets):** `platform.audio_capture` runs the game twice with `--fixed-step 16.667 --frames 120 --tap 3,106,165 --audio-capture` and compares the WAVs byte for byte (silent until #62 and #63 decode samples; since #62 it runs `--frames 180` and requires the tap's effect 43 in the capture). `runtime.boot_real`, `runtime.launch_real`, `platform.game_boot` (now on `SDL_AUDIO_DRIVER=dummy`) and `platform.device_golden` pass unchanged: the boot raises no AL error.
- **Manual:** `MapleThief --audio-test-tone` on a Mac mini: `audio: driver coreaudio, device "Mac mini Speakers": 44100 Hz, 2 channels, format 0x8120, 1024-frame buffer`; the stream pulled 79,872 frames in 78 calls, longest render 134 µs, 0 late callbacks. Listening is Joris's (#124).

## Consequences

- **#61** wrote the mixer, the effect voices, `alBufferData`'s copy, the pull API, the platform stream, `--no-audio`, `--audio-capture` and `--audio-test-tone`, the synthetic tests above, and the mixer side of the music voice.
- **#62** filled `ExtAudioFileRead` with real samples: `ExtAudioFileOpenURL` keeps a host copy of the WAV's first `data` chunk (the bounds-checked RIFF walk of ADR 0038: later chunks and odd-size padding skipped, a truncated last `data` chunk read up to its last whole frame); reads copy the next frames in the client format, bounded by `*ioNumberFrames`, the frames left and the one buffer's `mDataByteSize`, both set to what was read (0 at the end). It converts only what `MyGetOpenALAudioData` needs: integer PCM files of 8 (unsigned), 16, 24 or 32 bits, read in the file's own format or as 16-bit signed packed little-endian interleaved PCM at the **file's** rate and channel count (24/32-bit keep their top 16 bits, 8-bit is re-centred). A client format with another rate or channel count, float, big-endian, unsigned 16-bit, non-interleaved stereo or another depth is refused with `'fmt?'` (`kAudioConverterErr_FormatNotSupported`), a non-PCM one with `kExtAudioFileError_NonPCMClientFormat`, and the old client format stays. Effects now sound: `platform.audio_capture` runs 180 frames and requires effect 43 (the tap's select sound, `alSourcePlay(44)` at about 3.16 s) in the capture; `audio.real_wavs` decodes all 26 shipped WAVs (501,768 frames) through the game's calls with exact frame counts and bytes; `runtime.boot_real` checks that the game's 26 AL buffers hold them. Resampling or channel mixing, if a later need appears, belongs here, not in the mixer.
- **#63** writes a `mix::MusicStream` over dr_mp3 and drives `mix::music_*` from `AVAudioPlayer`'s `-play`, `-stop`, `-setVolume:`, `-setCurrentTime:` (`music_edit`) and its release (`music_remove`), in `avfoundation.cpp` and a new file; it does not need to change the mixer.
- **#64** stores master/music/effects volume and mute-on-unfocus in `settings.ini` (ADR 0043) and applies them with `mt_audio_set_gain` / `mt_audio_set_muted` from `platform/`; it does not need to change the runtime. The vibrate system sound goes to a rumble hook for #72.
- **CI** checks the mixer exactly with synthetic data, and real-asset tests check the decoded files and a scripted capture locally. Listening is a manual check (`needs-human` where an issue asks for it).
- **How we'd know this was wrong:**
  - **Dropouts in the soak test** (late callbacks, a long render): move music decoding out of the lock into a ring buffer, or raise the device buffer.
  - **Linear interpolation sounds wrong** on the 8 kHz effects next to device recordings: swap in a better interpolator behind the same voice step; the tests' expected samples change with it.
  - **A device's own rate makes SDL's conversion audible**: render at the device rate instead (the mixer's rate becomes a parameter; captures stay at 44,100).
  - **The game turns out to call `alBufferDataStatic` after all** (a trace shows the name returned NULL on a live path): add host-function addresses to the dispatcher and copy at the call, as `alBufferData` does.

## Addendum: the audio session, vibration and the user's volumes (#64, 2026-10-29)

- **AudioSession keeps the device's answers** (`runtime/src/audio/audio.cpp`). `AudioSessionInitialize` succeeds once and answers `kAudioSessionAlreadyInitialized` ('init') after that. `SetActive` and `SetProperty` answer `kAudioSessionNotInitialized` ('!ini') before it. A category ('acat') of the wrong size is `kAudioSessionBadPropertySizeError` ('!siz', was paramErr), a null one paramErr. Other properties are accepted. The interruption listener (`SoundPlayer_InterruptionListener` `0x1CBDD`) is kept and **never called**: a desktop has no phone call or alarm to interrupt it, and a window losing focus is the platform's mute below, not an interruption. The game's own `Clet_Pause`/`Clet_Resume` already stop and restart its sound around resign/become active. `AVAudioSession -setCategory:error:` answers YES. Tests (`gles_test.cpp`) register the listener's address as a counting guest function and run the session calls with the begin/end interruption sequence, renders and `AVAudioSession`: it is called 0 times.
- **Vibration is a host hook.** `AudioServicesPlaySystemSound(kSystemSoundID_Vibrate = 0xFFF)` (the game's only id: `CMSoundPlayer::Vibrate` with the vibration option on) calls `mt_audio_set_vibrate_hook(fn, user)`'s function on the guest thread, shaped like `mt_gfx_set_replace_hook`. It has no duration (the device ignores the game's milliseconds too) and is kept across processes. Every other id is counted and does nothing. The game's hook counts and logs at debug level (`game: N vibrations` at the end); #72 rumbles an open gamepad from it.
- **The user's volumes and mute-on-unfocus** live in `settings.ini` ([ADR 0043's addendum](0043-scaling-modes-mouse-mapping-and-settings-file.md#addendum-the-audio-keys-and-writing-the-file-64-2026-10-29)) and reach the buses through `mt_audio_set_gain` / `mt_audio_set_muted` from `platform/`. The mixer is unchanged.

## Addendum: the music stream (#63, 2026-10-29)

#63 built the music side as planned, without changing the mixer: `mt_audio::Mp3Stream` (`runtime/src/audio/mp3_stream.{h,cpp}`) is the `mix::MusicStream`, and `avfoundation.cpp` drives `music_play`, `music_stop`, `music_set_volume`, `music_edit` (`setCurrentTime:`) and `music_remove` (dealloc), keyed by the player's address. Where a pass starts and loops, and why, is [ADR 0046](0046-avaudioplayer-mp3-streams-and-loop-points.md). Decoding under the lock costs about 0.2 ms per 4,096-frame block in a Debug build (534 × real time), and the game on the Mac mini's speakers looped track 31 for 118 s with the longest render 325 µs and no late callback, so the ring buffer of *How we'd know this was wrong* isn't needed so far.

## Addendum: M6's exit criteria through the game (#124, 2026-10-30)

The criteria of *Context* are checked through the recompiled game's own sound code, not stand-ins (`tests/cpp/game_audio_real_test.cpp`, local, real assets; it boots the game to the main menu, then calls the game's functions from the run loop's turn hook with `mt_call_guest` and is the mixer's only reader):

- **All 44 sounds play when triggered** (CTest `audio.game_sounds`): `StopAllBGM` `0x1CF1D`, then `CMSoundPlayer::Play` `0x1D3B9` (id, resume 0) for every id. The 26 effects reach `alSourcePlay(g_soundSources[id])` and play exactly ⌈frames × 2³² / step⌉ output frames, then stop (27.82 s in all); the 18 tracks rewind (`setCurrentTime:0`) and play, still play 1 s past the end of their pass, and their second pass starts sample for sample like the first (825.94 s rendered). 42 has no call site in the game and is played through `Play` like the rest. The loop points: [ADR 0046's addendum](0046-avaudioplayer-mp3-streams-and-loop-points.md#addendum-the-loop-points-through-the-game-124-2026-10-30).
- **The music switches per map** (CTest `audio.game_map_music`): `CStateGame::PlayMapBGM` `0x81031` for all 90 shipped maps gives the generated table of [re/audio.md](../re/audio.md#map-music) (mtport.audio's transcription): 13 restarts, 77 resumes, each resumed track going on from the frame where it stopped. The `audio` trace's `-[AVAudioPlayer stop]` line now names that frame, and `-play` reads the position before the voice starts (the render thread may read the stream after that).
- **No dropouts over 30 minutes:** `MapleThief --seconds S` ends a run S seconds after the first run-loop turn (real or virtual time; CTests `platform.seconds_usage`, every build, and `platform.game_seconds`, real assets) and the exit log adds how long the device stream ran against the audio it pulled. The soak (2026-10-30, Mac mini, Debug build, `MapleThief --seconds 1800` on the default device with SDL's dummy video, master volume 10 %, Play tapped into a new game: the intro scene with track 30, effects 43 and 23, then Henesys with track 5, which then looped for about 28 minutes, and four effect 12s at its dialog): `audio: driver coreaudio, device "Mac mini Speakers": 44100 Hz, 2 channels, format 0x8120, 1024-frame buffer`; `game: audio: 79377408 frames rendered in 77517 calls (longest 332 us), 0 late device callbacks`; `game: audio: the device stream ran 1799.942 s and pulled 1799.941 s of audio (-0.001 s)`. **0 late callbacks**, the longest render 332 µs (7.5 % of a 1,024-frame period of 23.2 ms) while the guest thread composited at 33 ms a frame, so the ring buffer of *How we'd know this was wrong* is still not needed.
- Listening is Joris's (#124, `needs-human`).
