# 32. CoreFoundation: CF objects are guest ObjC objects, the bundle is the extracted .app, and the platform drives one run loop

- **Status:** Accepted
- **Date:** 2026-10-27
- **Issue:** #48
- **Builds on:** [ADR 0019](0019-import-thunks-and-hle-abi.md) (registry, data imports and their init hooks), [ADR 0025](0025-guest-memory-and-address-space.md) (guest heap), [ADR 0026](0026-objective-c-strategy.md) / [ADR 0029](0029-objective-c-runtime-services.md) (host classes, side-table state, autorelease pools), [ADR 0027](0027-process-start-up.md) (the boot's objc-image step), [ADR 0028](0028-libc-hle.md) (the configured clock, `MT_TRAP_ABORT`), [ADR 0033](0033-gcd-worker-threads-and-main-queue.md) (GCD's main-queue drain, which the run loop calls)

## Context

The armv7 slice imports 51 symbols from CoreFoundation: 14 Foundation class objects (`_OBJC_CLASS_$_NSData`, …, which #49 implements), 24 functions, 12 data objects and `___CFConstantStringClassReference` ([re/imports.md](../re/imports.md)). The functions and data:

- **Files.** `CFBundleGetMainBundle`, `CFBundleCopyResourceURLForLocalization`, `CFURLCreateDataAndPropertiesFromResource`, `CFStringCreateWithCString`, `CFDataGetLength/GetBytePtr/GetBytes`, `CFRelease`. `FUN_0000a2c0` reads every game file: it makes CFStrings from the C-string name and folder (`kCFStringEncodingASCII`), looks the file up with the localization `CFSTR("English")` (the literal at `0x117F44`) and reads it with `CFURLCreateDataAndPropertiesFromResource`. `FUN_00008f70` does the same for a URL it is given, asks for the properties dictionary too, and releases it.
- **The clock.** `RunLoopTimer_Arm` creates the game's only clock: one repeating `CFRunLoopTimer` on `CFRunLoopGetMain()` in `kCFRunLoopCommonModes`, with a first fire date from `CFAbsoluteTimeGetCurrent` and later `CFRunLoopTimerSetNextFireDate` calls ([re/program-flow.md](../re/program-flow.md)). `CFRunLoopGetCurrent` and `kCFRunLoopDefaultMode` are Chartboost's.
- **Sockets.** `CMSocket` uses `CFSocketCreate/ConnectToAddress/CreateRunLoopSource/GetNative/SendData/Invalidate` and `CFRunLoopAddSource`. The port is offline: the connect must fail fast ([re/network.md](../re/network.md), #23). The six `CFSocket*` functions are the offline stubs of #52 (`runtime/src/stubs/network.cpp`, [ADR 0034](0034-offline-services.md)), whose socket and source objects are plain `NSObject` instances; `CFDataCreate`, `CFRelease`, `CFRunLoopGetCurrent` and `CFRunLoopAddSource` around them are this ADR's.
- **Strings.** `CFStringAppendCharacters`, `CFStringConvertEncodingToNSStringEncoding`. The game converts its Korean table text with `kCFStringEncodingEUC_KR`, through `-[NSString initWithBytes:length:encoding:]` (#49), so the encoding tables belong here.
- **Data imports.** `kCFAllocatorDefault`, `kCFBooleanTrue/False`, `kCFNumberNaN/PositiveInfinity/NegativeInfinity`, `kCFRunLoopCommonModes/DefaultMode`, `kCFBundleIdentifierKey/VersionKey`, and `NSLocaleCountryCode/LanguageCode` (Foundation's names, bound from CoreFoundation). Each is a pointer-sized object the guest reads.
- **The 367 CFString literals** of `__cfstring` are `{isa, flags, chars, length}`. 366 are 8-bit (all ASCII), one is UTF-16: the Korean terms of service. Their `isa` is a bind to `___CFConstantStringClassReference`.
- **Toll-free bridging is used.** The game passes CF strings to `NSString` methods and `NSData` from Foundation to `CFDataGetBytePtr`; Foundation (#49) and UIKit text drawing (#51) need the same objects.

## Options considered

**The object model.**

1. **CF objects are host-only handles** (an index into a host table) and Foundation bridges them. Two object kinds for one guest pointer, and every NS method must test which one it has.
2. **CF objects are guest ObjC objects of host classes.** A `CFStringRef` is an `NSString *` because both are the same guest object of a host class (`__NSCFString`). Contents live in the object's host state (`mt_objc_state`, ADR 0029) and retain counts in the runtime's side tables, so `CFRelease` and `-release` are the same message.

**String storage.** (a) Guest bytes in the object, as CF does. (b) Host `std::u16string` in the object's state, with guest copies only where the guest needs a pointer (`-UTF8String`, `CFStringGetCStringPtr`).

**The bundle.** (a) Copy or convert the bundle into a runtime-owned layout. (b) Read the extracted `.app` in place (`work/ipa/Payload/MapleThief.app`), configured by path.

**The run loop.** (a) A guest-visible `CFRunLoopRun` that the boot enters after `UIApplicationMain`. (b) The platform layer owns the loop and calls one turn at a time.

## Decision

- **Files.** `runtime/include/maplethief/cf.h` (public C API: configuration, start, the run loop), `runtime/src/cf/cf_objects.h` (the object model and storage API for Foundation and UIKit), `runtime/src/cf/cf_hle.h` (the HLE entry points), and in `runtime/src/cf/`: `cf.cpp` (lifetime, numbers, data imports), `string.cpp`, `data.cpp`, `encoding.cpp` with the generated `cp949_table.inc`, `bundle.cpp`, `runloop.cpp`, `bridged_classes.cpp`. Registry entries and host classes are added under `#ifndef MT_HLE_CORE_ONLY`.
- **Objects** follow option 2. The bridged classes are host classes: `NSString` → `NSMutableString` → `__NSCFString` → `__NSCFConstantString`; `NSData` → `NSMutableData` → `__NSCFData`; `NSValue` → `NSNumber` → `__NSCFNumber` / `__NSCFBoolean`; and `__NSCFType` for the CF-only types (run loop, timer, run-loop source, socket, bundle, URL), each with its own state type. Instance sizes are 8 bytes (16 for a constant string, the literal's size). Constant strings, booleans and the CF constants are **immortal**: their `-retain`, `-release` and `-retainCount` overrides do nothing (retain count `UINT_MAX`), as on iOS.
- **Constant strings.** The ObjC start-up binds `___CFConstantStringClassReference` to the class object of `__NSCFConstantString` (the same list as the other class binds in `objc.cpp`), so every literal is an object of that class with no copying. Its text is decoded on first use from the literal: flags `0x7C8` 8-bit (UTF-8, Latin-1 if that fails), `0x7D0` UTF-16. The runtime makes its own constant strings the same way, in guest memory.
- **Strings** follow option (b). The state is the UTF-16 text, a mutable flag, a version and NUL-terminated guest copies per encoding, cached per version and freed at `dealloc` (a copy stays valid after a mutation, like the autoreleased buffer of `-UTF8String`). **Data** keeps its bytes in one guest heap block because `CFDataGetBytePtr` returns a guest pointer.
- **Encodings.** ASCII, ISO Latin-1, UTF-8, `kCFStringEncodingUnicode` (little-endian unless a BOM), UTF-16BE/LE, EUC-KR (KS X 1001, strict) and DOS Korean / CP949 (EUC-KR plus the 8,822 extension syllables, computed). The KS X 1001 table is generated from Python's `euc_kr` codec by `tools/mtport/cp949.py` into `runtime/src/cf/cp949_table.inc` (committed: it is our generator's output from a standard, not from the game), which the generator's test checks against Python's `cp949` codec. MacRoman is not supported (no game path uses it): a conversion logs and fails. `CFStringConvertEncodingToNSStringEncoding` maps the encodings Foundation names (UTF-8 → 4, …) and otherwise sets bit 31 (EUC-KR → `0x80000940`).
- **The bundle** is option (b). `mt_cf_config {bundle_dir, bundle_path, language}` names the host directory of the extracted `.app`, the path the guest sees (default `/var/mobile/Applications/00000000-0000-0000-0000-000000000000/MapleThief.app`) and the language (`en` or `ko`). `MAPLETHIEF_BUNDLE_DIR` and `MAPLETHIEF_LANGUAGE` set them through `mt_cf_config_from_env`; an unconfigured runtime reads the environment once. The bundle is indexed once per configuration with exact case, so lookups behave the same on case-insensitive and case-sensitive file systems, and a path with `..` is rejected. `CFBundleCopyResourceURLForLocalization(bundle, name, type, subdir, loc)` looks for `<subdir>/<name>[.<type>]` unlocalized first, then in `<loc>.lproj/` and its alias (`English` ↔ `en`, `Korean` ↔ `ko`, `Japanese` ↔ `ja`). With no localization it tries the configured language, then English. The URL is a `__NSCFType` that remembers the bundle-relative path. `CFURLCreateDataAndPropertiesFromResource` reads the file into a new CFData, returns an empty `NSDictionary` for properties when that class exists (else NULL, logged) and error code 0, or `false` with error code −12 (`kCFURLResourceNotFoundError`) for a missing file.
- **The run loop** is option (b). There is one main run loop (immortal). `mt_runloop_run_once(cpu, now)` is one turn: push an autorelease pool, call the per-turn sources (`mt_runloop_add_turn_source`, in registration order: per-frame work of the platform layer), fire every timer of the default or common modes whose fire date is ≤ `now` once (earliest first, then in creation order), deliver the offline stubs' deferred callbacks with `mt_stubs_pump` (#52: GameKit and StoreKit completion handlers and delegate callbacks posted before the pump), drain GCD's main queue with `mt_gcd_drain_main` (ADR 0033: the due `dispatch_after` timers, the worker threads, then the main-queue blocks queued before the drain started), and pop the pool. **Why this order:** the per-turn sources come first so the platform's per-frame work (input) is seen by the frame the timer draws; the timer is the game's frame, as on iOS where a turn's timers fire before the main queue is serviced; the stubs' deliveries stand in for framework callbacks arriving on run-loop sources, and they go before the GCD drain because the game hands GameKit results to the main queue with `dispatch_async`, so that block runs in the same turn instead of one frame later; the drain is last, and what it queues waits for the next turn (libdispatch's rule). The timer is retained during its callout. A repeating timer whose callout did not set a new fire date moves to the next point of its interval grid after `now`, skipping missed fires as CF does; a one-shot timer is invalidated. The turn returns `mt_runloop_next_wake(now)`, the earlier of the next timer fire date and GCD's next deadline (`now` while GCD work or a stubs delivery is waiting, `MT_CF_DISTANT_FUTURE` if nothing is scheduled), so the platform layer knows how long it may sleep. Timers added in other modes never fire (logged). A nested call only logs. Timer contexts' retain/release callbacks are honoured.
- **Time.** `CFAbsoluteTimeGetCurrent` is the libc's configured clock (ADR 0028, the same as `gettimeofday`) in seconds since 2001-01-01, so a test can drive both from one fake clock. GCD keeps its own monotonic nanosecond clock (`mt_gcd_configure`), as on iOS, where `dispatch_time` counts `mach_absolute_time` and `CFAbsoluteTime` is the wall clock: CF does not configure GCD's clock, because a wall clock may jump and GCD's configuration belongs to whoever owns the process (it can only change while no worker thread exists). `mt_runloop_next_wake` converts GCD's deadline by the distance between `mt_gcd_now()` and the turn's `now`.
- **Run-loop sources.** `CFRunLoopAddSource` accepts any object (#52's socket source is a plain `NSObject`), retains it once like CF and never signals it. The game imports no way to remove a source, so one small object per failed connect stays until the process ends. `CFRelease` of any object is a `release` message (toll-free), so it works on #52's objects too.
- **Data imports.** The registry gives each of the 12 an init hook. The hooks only record the slot, because the boot places data imports before the ObjC runtime exists; `mt_cf_start(cpu, rt)`, which the boot calls in its objc-image step after the host classes are added, creates the objects and fills the slots (its count is in the step's log line, "12 CF constants"). `kCFAllocatorDefault` is NULL; the booleans are `__NSCFBoolean`s; the number constants are `__NSCFNumber` float64s; the string keys are constant strings with Apple's values (`kCFRunLoopCommonModes`, `CFBundleIdentifier`, `kCFLocaleCountryCodeKey`, …).
- **Misuse stops the guest.** A NULL or wrong object where CF would crash (`CFRelease(NULL)`, `CFDataGetLength` of a string, appending to an immutable string) logs `cf: <function>: <what>` and calls `mt_trap(MT_TRAP_ABORT, lr, obj)`. `CFDataGetBytes` with a range past the end logs and copies the part in range.
- **NSString's first two methods.** `+[NSString stringWithUTF8String:]` (an autoreleased `__NSCFString`; nil for invalid UTF-8; NULL is a misuse) and `-[NSString UTF8String]` (a guest copy owned by the string) are in `bridged_classes.cpp` now, because the offline stubs (#52) send them before Foundation exists; the real NSString replaced #52's test double.
- **Extension points.** *(Amended by [ADR 0035](0035-foundation-subset.md): Foundation's selectors, `+stringWithUTF8String:` and `-UTF8String` included, are host categories in `runtime/src/foundation/`, and `bridged_classes.cpp` keeps only the CF behaviour.)* Foundation (#49) adds NS selectors to the method tables of `bridged_classes.cpp` and works through `cf_objects.h` (`string_chars`, `string_create(_bytes)`, `string_guest_cstring`, `data_*`, `number_*`, `encode`/`decode`, `bundle_find/read/host_path/guest_path`, `url_create`). UIKit (#51) reads strings with `string_chars` and images with `bundle_*`. The platform layer (#54, #117) configures the bundle and drives `mt_runloop_run_once`.

## Consequences

- **Tests.** In CI, the doctest cases of `tests/cpp/cf_test.cpp` (in `objc_test`) cover every function and data import over a synthetic bundle directory: lifetime and immortality, literal decoding, every encoding (with CP949 and EUC-KR round trips), bundle lookup with localizations and aliases, the run loop's ordering, grid, one-shot, mode and context rules against a fake clock, one turn that runs a per-turn source, a due timer, a stubs delivery, a `dispatch_async` block, the block the delivery queued and a due `dispatch_after` block in that order (with the wake-up time from GCD's deadline), `CFRunLoopAddSource` and `CFRelease` on plain `NSObject`s (#52's socket objects), and each misuse trap. `tests/test_cp949.py` checks the table generator. Locally, `cf.real_bundle` (`tests/cpp/cf_real_test.cpp`) reads all 2,172 files of the shipped `.app` through the game's own two calls and compares their bytes, checks `Scripts.strings` in English and Korean, and decodes all 367 literals; `tests/test_hle_cf_real.py` checks that every CoreFoundation function and data import of the slice has a registry entry; the real boot test still reaches `UIApplicationMain` with no unimplemented import.
- **NS classes exist before Foundation.** `NSString`, `NSData`, `NSNumber` and their subclasses are real host classes now, not placeholders, but with only the CF behaviour and `NSObject`'s methods until #49 adds theirs.
- **CFURL is not bridged** to `NSURL`; when #49 needs `NSURL` it either becomes the URL's class or wraps the bundle path.
- **How we'd know this was wrong:**
  - **A file is missing or wrong at run time.** A lookup fails that the device makes (a localization, a case difference, a folder layout we did not foresee). The log line names the request, and `cf.real_bundle` covers every shipped file through the game's own calls.
  - **Timing differs from the device.** If the game's frame clock drifts or bunches up, the grid rule (missed fires skipped) or the fire order is wrong; the cf_test cases pin CF's documented behaviour.
  - **Bridging needs more than one object kind.** If #49 finds a Foundation behaviour that cannot live on these classes (for example an `NSString` subclass from the guest that CF functions must accept), CF functions need to send messages for non-CF strings instead of reading state.
  - **A Korean string fails to decode.** The strict EUC-KR decoder returns NULL like CF; the game's tables are all plain EUC-KR today ([ANALYSIS.md](../ANALYSIS.md)).

## Addendum: Mac OS Korean (#127, 2026-10-30)

`CChatBox::drawRequire` (`0x3243D`) converts the name of each etc item a quest asks for with `+[NSString stringWithCString:encoding:]` and NSStringEncoding `0x80000003` (`kCFStringEncodingMacKorean`, 3), then copies the result's C string with `strcpy`. Unsupported, the string was nil and the guest faulted on a NULL read as soon as a quest offer such as Humanoid's ("8 Blue Snail Shells") showed its request. Mac OS Korean is KS X 1001 in the EUC-KR layout plus Apple's symbol extensions, which no game text uses, so `k_enc_mac_korean` decodes and encodes as strict EUC-KR. English item names are ASCII and pass through unchanged. Tests: `cf_test` (round trip, NS ↔ CF numbers) and `foundation_test` (`stringWithCString:encoding:` with `0x80000003`).
