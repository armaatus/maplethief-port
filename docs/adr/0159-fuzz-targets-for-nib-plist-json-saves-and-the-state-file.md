# 159. Fuzz targets for NIBArchive, binary plists, JSON, saves and the state file

- **Status:** Accepted (delegated by Joris, 2026-11-13)
- **Date:** 2026-11-13
- **Issue:** [#323](https://github.com/armaatus/maplethief-port/issues/323) (epic [#287](https://github.com/armaatus/maplethief-port/issues/287))
- **Builds on:** [ADR 0158](0158-libfuzzer-targets-and-the-fuzz-smoke.md) (the targets' pattern, the smoke, the long runs), [ADR 0154](0154-threat-model-for-player-supplied-files.md) (the parsers to cover), [ADR 0157](0157-asan-and-ubsan-preset-and-ci-job.md) (the sanitizers), [ADR 0105](0105-save-states-in-process-snapshot-at-safe-points.md) (the state file and its sections), [ADR 0084](0084-offline-polish-hidden-online-ui-local-game-center.md) (`gamecenter.json`)

## Context

ADR 0154 gives each parser of an untrusted file a fuzz target; ADR 0158 set how a target is made (`tests/fuzz/NAME_fuzz.cpp`, seeds generated by `seeds/NAME.py`, `maplethief_add_fuzz_target`, a 30 s CI smoke, long runs counted in CPU time). #323 covers the structured formats: NIBArchive (`uikit/nib.cpp`), binary plists (`foundation/plist.cpp`), JSON (`stubs/json.cpp`, `gamecenter.json`), the save files (`foundation/saves.cpp`) and the state file (`snapshot/state_file.cpp`) with the load function of every section (ADR 0105): 9 sections of `snapshot.cpp`, 18 modules' and 39 host state serializers'.

A read of the code before this issue found two edge cases: the plist reader expands shared references, so memory grows with the number of references times the size of the object they share; and the JSON reader turned a lone surrogate (`"\ud800"`) into the bytes of an encoded surrogate, which is not UTF-8.

The state file needed more thought than the others. Its sections are only meaningful to a runtime with the same layout (the guest's segments, stacks and heap, the ObjC tables), each is checked by a CRC before it is read, and a seed in Python cannot know a section's bytes.

## Options considered

**The state file's sections.**

1. **One program per section** (66). A clean target each, but 66 builds and 66 CPU-hours of long runs for code that is mostly the same.
2. **Whole state files only.** Each section's CRC would have to be right for its reader to run: the fuzzer would spend its time on CRCs.
3. **One target that edits a baseline** (this ADR). The target builds a synthetic guest in `LLVMFuzzerInitialize` (the one `snapshot_test.cpp` restores, with a live host state of most serializers) and saves its state once: the baseline. An input names what it edits, `file`, a section's name or `state:<serializer>`, then a mode (replace, overwrite, overwrite and cut, insert, cut), an offset and bytes. The edited section is written back into the file with a good CRC and the file restored, so the edit reaches its own reader with every other section valid; a serializer's payload is loaded on a zeroed block as a restore loads it. The seeds are one line per name (`seeds/state.py`), and the fuzzer starts each from the baseline's real bytes.

**The plist's shared references.**

1. **Refuse a shared reference.** CFBinaryPList writes them for repeated strings; the bundle's tables could use them.
2. **Bound the bytes copied** (this ADR): besides the bound on objects (count × 16 + 4,096), the data and string bytes copied by all expansions together are at most the file's size × 16 + 4,096. A file that shares a large object many times is refused with "shared references copy too many bytes". Memory stays linear in the file's size (ADR 0154, guarantee 3).
3. **Keep shared objects shared** (a DAG instead of a tree). Right in principle, but every caller walks `PlistValue` as a tree.

**The JSON lone surrogate.**

1. **Replace it with U+FFFD.** Accepts a file the port never writes.
2. **Refuse it** (this ADR): a high surrogate must be followed by `\u` and a low one, and a low one alone is refused, both with "lone surrogate". The port's writer never escapes a surrogate, so no `gamecenter.json` it wrote is refused; the text pack reader (ADR 0108) refuses them too.

## Decision

Decided by the agent (delegated by Joris, 2026-11-13); Joris can veto it in the PR.

1. **Five targets** in ADR 0158's pattern, each with its seed module and a dictionary where it helps: `nib`, `plist`, `json`, `saves` and `state`.
2. **What each checks besides the sanitizers** (a failed check is `__builtin_trap()`): every refusal has a reason. `nib`: every index an accepted archive holds is in range, and the accessors `uikit/app.cpp` uses run over it. `plist`: an accepted file's expansion stays inside the reader's bounds. `json`: a text of valid UTF-8 gives strings of valid UTF-8, and the writer's output of an accepted tree parses again to the same tree. `saves` (a first byte picks the file name and the size of the reason's buffer): the reason is NUL-terminated inside its buffer, the verdict does not depend on that buffer, the sanitiser changes only `config`, at most two bytes, never a file the checks pass, and a second pass changes nothing; the cash shop's counters parser reads the counters files. `state`: a refused restore changes nothing (the guest saved again equals the baseline, section by section), an accepted one is undone by restoring the baseline, which must succeed, and no guest code runs (`no_guest.cpp`).
3. **The state target** as option 3 above. `tests/test_fuzz_state_seeds.py` checks that `seeds/state.py` names every section and serializer the runtime registers, so a new one gets a seed. 26 of the 39 serializers have a live state in the synthetic guest (the values, CG, UIKit views, controllers and layers, fonts, GameKit, a StoreKit request); the other 13 (the audio player and session, the bundle, the run loop and its timer and sources, the socket, the gradient, the GL context, StoreKit's responses, products, payments and transactions) start from an empty payload.
4. **The two edge cases** are fixed as above, each with a test that fails without its fix: `Foundation: a binary plist's shared references are bounded by the bytes they copy (#323)` and `gamecenter.json's JSON: a lone surrogate is refused, not made invalid UTF-8 (#323)`.

## Consequences

- Every parser of ADR 0154's second group, and every section and serializer of the state file, has a target; their rows in ADR 0154 name it.
- The state target runs at a few hundred inputs a second (each one writes and restores a state file and saves the guest again to compare), the parsers at tens of thousands.
- A seed of the state target follows the runtime: when a section's layout changes, the baseline changes with it, and nothing in git goes stale.
- A plist that shares one large object for more than 16 times its own size is refused. None of the bundle's does (`foundation.real_bundle`, and the plist target's checks over every shipped plist and `.strings` file).
- A `gamecenter.json` with a lone surrogate is unreadable, kept aside as `.bad` at the next save (ADR 0084).
- How we'd know this is wrong: a crash in one of these parsers from a file in the wild, or a state target whose coverage stops growing within minutes of a long run (then the edits or the synthetic guest miss a path: add live states to it).
